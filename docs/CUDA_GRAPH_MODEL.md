# CUDA Graph 生命周期与独立成本

本次实现把 llama.cpp 的 Graph 生命周期接入实际仿真任务图。Graph 开关本身不能证明重放；开启后没有完整绑定的任务会报错，不会悄悄使用普通提交成本。

## 支持路径

- 固定 llama.cpp 源码版本：`d3146f2b56c2db4711ac8391871c9e529d1946d7`。
- 单 GPU、单序列，显式启动探测、两次预热及正式请求；上下文检查点关闭。
- `tools/cuda_graph_structure_probe.cpp` 调用固定版本的 GGUF 图构建器；dry 模式不执行 CUDA 模型，capture-only 模式构建结构但不实例化或重放。
- 仿真读取完整节点属性、UID、graph key，以及 kernel/memcpy 节点和依赖边，自己推导首次直接执行、稳定后捕获、属性变化后重新预热、更新及重放。live 记录仅核验，不作为预测决策输入。
- 这是依赖 native 图构建器的源码辅助路径；尚未实现独立的 Python GGML 图编译器。未覆盖的图结构、更新约束、缺失成本会报错。

## 成本边界

CPU 提交、捕获、实例化、更新、首次提交、后续提交、销毁分别计价。更新失败使用旧图到新图的独立测量，销毁使用被销毁对象的结构。CPU 提交在单独资源上执行，允许与 GPU 计算重叠；GPU kernel 和物理 DRAM 任务保留。

独立 CUDA API 测量已经覆盖 host driver submit。对同一设备、同一物理调用组且具有独立成本所有者的提交，旧 cohort driver-submit 任务保留身份与依赖，移除其重复服务需求，并记录成本归属替换。缺失或不唯一的匹配会报错。CPU command build、GPU command processor、kernel launch、GPU 计算和 DRAM 费用不因此移除。修复前本轮每次调用另计 250ns；正式 128 次调用累计 32µs 服务量，此和不等于 E2E 差值，修复后须重新仿真。

CUDA event 间隔只用于诊断，不作为额外 GPU 成本相加。设备端调度仍使用原分析参数，Graph 带来的设备调度收益尚未独立校准。普通异步提交总成本按模型 launch 任务等分，是明确保留的分配假设。

本机 GPU 预设每个 kernel 的 1000ns launch 延迟来自可编辑分析默认值，尚无独立证据证明它完全属于设备侧、与 host API 耗时没有重叠。因此本轮保留该参数，并明确不宣称 CPU/设备提交成本已全面拆分验证。采样的候选物化、编译器缓存与过滤链成本，以及完成中断延迟仍不完整；报告中的 partial 标记应保留，这些缺项的数值影响尚未独立量化。

## 两种成本入口

`runtime_measurement_mode="qualified"` 使用 `RuntimeResidualCalibration`。独立训练点和验证点分离，按结构、节点数区间和阶段检查，不允许外推。当前通用插值测量没有通过全部条件，不能宣称已经校准成功。

`runtime_measurement_mode="experimental_exact_structure"` 使用 `RuntimeStructureMeasurements`，仅接受已独立测量的确切节点数和类型化拓扑，并报告重复值、中位数、MAD、范围。它不允许插值或外推，也不会获得 `prediction_qualified=true`。合成 kernel 的函数、参数、执行体与真实模型不同；重复值的散布只衡量测量波动，不能当作真实模型上的成本误差。

两种入口均禁止同时添加旧标量提交成本，避免重复计价。不同 profile 的硬件与 runtime 命名空间通过显式双向身份绑定关联，不通过改写测量来源来制造一致性。

## 对照方法

5 个本地 GGUF：Qwen3 0.6B F16、1.7B Q8_0、4B Q4_K_M、8B Q4_K_M，以及文件名为 Qwen3.8 27B 的 IQ3_S/IQ4_XS 混合模型（GGUF 实际架构为 qwen35）。

输入 512 / 输出 128，context 768，batch/ubatch 512，FP16 KV，Flash Attention 关闭，单序列，无 MTP、无提示缓存。控制实验在两侧均显式关闭上下文检查点；此前默认检查点数据单独保留。

原始未插桩 native server 每组两次预热、五次正式样本。另用诊断构建验证实际重放并丢弃诊断耗时。前端导入 JSON，点击运行，再记录实际提交、任务编号和完成报告。仿真显式模拟启动和预热，比较最后正式请求的 engine TTFT、TPOT 和 E2E，不混入队列等待与 HTTP 时间。

误差为 `(仿真 - native 中位数) / native 中位数`，同时保留绝对误差与 native 散布。Graph 收益由同模型的 on/off 对照计算。所有 LLM 耗时只用于最终验证，未用于调整成本参数。

结果入口：[本机对照报告](cuda_graph_validation_2026-10-08/report.html)。报告中“已配对”必须同时满足前端提交配置一致、物理计算/DRAM 实际参与、结构程序完整消费及实际 Graph 诊断，不能只凭任务成功或开关开启。

## 性能修复的数值影响

物理阶段解析缓存不再跨批次持有完整任务图；可重建的完整调用模板最多保留 8 份，其他叶级缓存容量不变。此调整不删除任务、DRAM 访问、依赖或资源需求。真实 F32 单层场景的 12 次编译检查中，完整阶段图的缓存保留数从 12 降为 0；淘汰后重建的任务、元数据、需求及 53 条执行事件逐项相同，时间线差为 **0 ns**。这是缓存等价性检查，不代表整个进程占用或 native 预测误差为零。

driver 提交去重属于计价修正，会改变预测。真实单层 51 个设备任务的专项检查中，Graph on/off 都减少 **250 ns**；物理访问需求、字节数、能耗、行和突发计数保持一致。时间戳相减的最大浮点舍入差为 **2.605×10⁻⁹ ns**。整请求差值必须读取完整重跑结果；不能把 128×250 ns 的服务量直接当作 E2E 改变量。全模型对照仍保留当前预测与 native 的实际误差。
