# HBM4 仿真参数资料需求清单

整理日期：2026-11-09。用途：与设计部门沟通，补齐 HBM 仿真中目前只能靠假设的参数。

## 背景

我们的 LLM 推理仿真器按 JEDEC HBM4（JESD270-4A）命令级建模 HBM：ACT/PRE/RD/WR/REF 命令、bank 行状态、时序约束和控制器调度都会显式执行。公开的 JESD270-4A 只给出组织结构和少数时序下限，**AC 时序表中大部分最小值是空白**，要由厂商按速度档填写。因此目前有十几项关键时序是工程假设。几何结构和命令合法性已经可以核对，但时序数值无法说明是准确的。

需要的资料分五类。P0 会直接影响现有结论，P1 用于校准，P2 是补充。

## A. 器件选型（P0，是后续各项的前提）

1. 目标 HBM4 料号或厂商；如不能透露厂商，至少提供以下各项。
2. 单 die 密度（24 Gb / 32 Gb）与堆叠高度（12H / 16H），以及每 GPU 的 stack 数。
3. 速度档：pin 速率（Gb/s）和对应 tCK。
4. 是否采用定制 base die（logic die）。如果部分控制器功能放在 base die 中，请说明放了哪些。

## B. AC 时序表（P0，对应速度档）

请按 A 项所选速度档提供。单位用 ns，或者用 nCK 并注明 tCK；注明是 min、typ 还是 max，以及规格书版本号。

| 符号 | 含义 | 当前值 | 当前来源 | 优先级 |
|---|---|---:|---|---|
| tRCDRD / tRCDWR | ACT 到 RD / WR | 14 / 14 ns | 工程假设 | P0 |
| tRP | PRE 到 ACT | 15.36 ns | JEDEC IDD 示例值，非 AC 保证 | P0 |
| tRAS | ACT 到 PRE 最短 | 33.28 ns | JEDEC IDD 示例值，非 AC 保证 | P0 |
| tRC | 同 bank ACT 间隔 | 48.64 ns | 推导：tRAS + tRP | P0 |
| tRRDS / tRRDL | 不同 / 相同 bank group 的 ACT 间隔 | 4 / 6 ns | 工程假设 | P0 |
| tFAW | 四次激活窗口 | 20 ns | 工程假设 | P0 |
| tRFCab / tRFCpb | 全 bank / 单 bank 刷新时间 | 450 / 240 ns | JESD270-4A 表值 | P0（确认厂商值） |
| tREFI | 平均刷新间隔 | 3.9 µs | 规范参考值，未考虑温度 | P0（含高温档） |
| tRREFD | REFpb 间隔 | 8 ns | 规范 max(3 tCK, 8 ns) | P1 |
| tWR | 写恢复 | 15 ns | 工程假设 | P1 |
| tRTP | RD 到 PRE | 6 nCK | 工程假设 | P1 |
| tWTRS / tWTRL | 写到读切换 | 6 / 8 nCK | 工程假设 | P1 |
| tRTW 及 PHY 项 | 读到写切换；tDQSS、tWDQS2DQ、tDQSQ 等 | 18.56 ns | 规范公式 + 假设的 PHY 项 | P1 |
| tCCDR | 跨 SID 的连续读 | 4 nCK | 规范允许范围内取的参考值 | P1 |
| RL / WL | 读 / 写延迟（模式寄存器编码） | 32 / 8 nCK | 合法编码中选的参考值 | P2 |
| tCCDS / tCCDL / tPPD | 列命令 / PRE 间隔 | 2 / 4 / 2 nCK | 规范下限 | 仅需确认 |

P0 的依据：现有分析显示，405B HBM4 SHORT 配置的 KV 读带宽受行冲突后的 tRP 与 ACT 顺序约束，刷新使 TPOT 增加约 5.7%。这几项直接决定 HBM4 的结果，也就决定了 HBF+ 与 HBM4 的比较。

## C. GPU 侧内存控制器与地址映射（P0 / P1）

这部分不属于 JEDEC，由 GPU 设计决定。现有数据表明，它对结果的影响可能大于 B 类时序。例如 HBM4 TP8 配置的行命中率只有 0.557，行未命中主要来自地址映射和请求次序，而不是规范本身。

| 项目 | 当前假设 | 优先级 |
|---|---|---|
| 物理地址 → stack / channel / PC / SID / bank group / bank / row / column 的映射 | 线性混合基映射，无 XOR 散列 | P0 |
| 跨 stack、跨 channel 的交织粒度 | 64 B 条带：同一 PC 的两个 bank group 各放一个 32 B 突发，然后换下一个 PC | P0 |
| 调度策略 | 每 PC 独立的 FR-FCFS，只在同一批请求内重排 | P0 |
| 页策略（open / close / 自适应、超时关页） | open page | P1 |
| 每 PC 读 / 写队列深度 | 32 / 64（取自 gem5 默认值） | P1 |
| 写队列排空水位、读写切换策略 | 高 0.85 / 低 0.50，每次切换至少 16 个读 | P1 |
| 刷新策略（REFab 还是 REFpb，可延后几次，是否插空刷新） | REFpb，按 bank 顺序，最多延后一个 tREFI | P1 |
| Row-hammer 缓解（RFM / ARFM / DRFM）的触发频率 | 未建模 | P2 |
| ECC / 数据奇偶校验是否占用有效带宽 | 未建模 | P2 |

## D. 实测或表征数据（P1，用于校准）

有以下任何一项，就可以从"自洽"推进到"校准"：

1. **单 stack 微基准**：顺序读、随机读、读写混合下的实测带宽占峰值的比例，以及负载-延迟曲线。数据来自芯片实测、厂商表征或控制器 RTL 仿真均可。
2. **刷新开销实测**：常温与高温下有效带宽的损失。
3. **内部周期精确模型**：如果设计部门有 HBM 控制器的 cycle-accurate 模型或 RTL 仿真环境，这是最有价值的对照方式。我们导出 LLM 解码阶段的真实 HBM 请求序列，由对方的模型运行，再逐条比较完成时间和带宽。这样能同时检验 B 类和 C 类参数。我们这边需要补一个请求序列导出脚本，格式可以按对方工具的输入要求定。

## E. 交付格式与使用范围

- 每个数值请附速度档、温度条件、规格书或文档版本号。
- 请说明可使用的范围：是否允许在论文中出现原始数值，还是只能出现归一化结果或定性结论。
- 我们会把这些数值标注为来自厂商或设计资料，并记录文档版本。未拿到的项目继续标注为假设，不会混用。

## 拿到资料后我们做什么

| 拿到 | 能做的事 |
|---|---|
| A + B | 建立 HBM4 设计参数组，替换当前从 HBM3E 沿用的假设值；在真实速度档附近设定敏感性范围，重跑 30 个候选点，检查部署选择与排序是否翻转 |
| C | 修正地址映射与调度。这是目前已知结构性不确定最大的部分 |
