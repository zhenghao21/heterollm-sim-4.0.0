# 严格 HBF 的 HOST DRAM 写入暂存

启用后，不满 4 KiB 页的逻辑写入先经过实际链路写入 HOST DRAM。写满一页后，读出 HOST DRAM、经过链路，再提交完整页给严格 HBF 核心。完整对齐页直接经计算端到 HBF 的链路写入。Attention 可以同时读取 HBF 中已刷新的部分和 HOST DRAM 中尚未刷新的尾部。

这是显式的主机侧写合并与地址管理策略。HBF 核心仍执行原有完整页写入、顺序编程及擦除规则；没有切换到 generic NAND，也没有把主机接收时间当作介质写完时间。该策略不是 OCP 规范强制指定的唯一实现方式。

## 配置

在使用 `hbf_ocp_0_7` 物理预设的 HBF 组件 metadata 中增加：

```json
{
  "host_write_staging": {
    "host_component_id": "hostmem0",
    "capacity_bytes": 67108864,
    "reserve_blocks": 1
  }
}
```

`capacity_bytes` 是从实际 HOST DRAM 分配器预留的预算，会与其他主机分配竞争容量。它必须是 4096 B 的整数倍，最少 8192 B，其中一页用于重写和回收的临时空间。上面的 64 MiB 只是配置示例，需要作为实验参数固定并记录。

`hostmem0` 必须是具有 DRAM 物理配置的 `host_memory` 组件。拓扑必须能解析计算端、HOST DRAM 与 HBF 之间的双向通路。路径的带宽、延迟和队列深度参与计时；缺少主机内存或必要路径会报错。

HBF 预留一个完整擦除块用于回收，因此可用介质容量低于标称容量。`reserve_blocks` 只支持 1，可以省略。严格 HBF 本身的 `write_buffer_bytes` 仍为 0。

## 行为与计费

- 缓冲未满页：在 HOST DRAM 中保留有效字节，后续读取通过主机内存和返回链路完成。
- 满页：提交严格 HBF 编程，相关逻辑写入的完成时间包含刷写完成时间。
- 原本完整对齐的页：直接传输到 HBF，不额外经过 HOST DRAM；覆盖旧页仍遵守地址重映射和回收规则。
- 主机空间不足：提前刷出最久未使用的暂存页。未写部分填充，但填充不使这些字节变成有效 KV；之后更新已刷页会执行读改写和地址重映射。
- 介质空间回收：保留仍有效的数据，计入读取、HOST DRAM 临时操作、链路、编程和擦除成本。回收属于本仿真的主机地址管理策略。
- 请求结束：释放该请求的 KV 和未满页尾部，不为已经无用的数据追加一次持久化写入。不同请求、分配代际与别名保持隔离。
- 常驻权重：仅显式声明的已加载权重可在测量前注册为介质内容；块尾填充计入容量。动态 KV 和激活必须有实际写入，读取未初始化数据会报错。

当前常驻权重采用按缓冲区分配完整擦除块的布局，并在已分配块之间条带化。小于一个块的权重缓冲区不会自动铺满所有 bank；块尾浪费和可用并行度都可能影响小模型结果，正式实验应记录这一布局假设。动态页按可用 bank 条带分配，独立页由真实资源日历决定并行度。

通用独立 RoPE 路径会为每次调用生成按 Q/K 广播展开的 sin/cos 表，再通过显式依赖读取；表与其他临时激活具有相同的生命周期，不作为预加载权重。表生成按每元素两次普通运算和一次超越函数评估计费，写入完整表；这个分析模型同时用于 HBM 和 HBF，并未假设跨层或跨调用共享表。真实 Qwen 的 QKV bias 会使该路径与 QKV 投影分离。

任务结果的 `physical_execution_by_owner` 分别记录 HOST DRAM、链路与 HBF 的真实操作；`hbf_host_staging` 记录逻辑字节、刷写、压力刷写、读改写、回收和当前占用。`host_occupied_bytes` 不包含单独列出的 `host_reserved_bytes` 临时页；`media_occupied_bytes` 包含逻辑页预留及权重块尾填充，`media_reserved_bytes` 是额外的回收预留。

物理裸地址的批量服务无法表达逻辑缓冲身份和路由，因此启用此策略后必须通过正式任务执行路径，不能用 `PhysicalService.price_batch` 绕过暂存状态。

## 全 HBF 实验

可以移除全部 HBM 组件，将 GPU 的活动内存指向 HBF，并保留 CPU、HOST DRAM 和相应链路。比较固定 GPU 计算侧时，应将模型算子明确放置在 GPU，避免自动放置策略把计算转到 CPU。权重、KV、激活及工作区由该 HBF 后端承接；暂存页仍实际占用 HOST DRAM。这是“无 HBM、允许 HOST DRAM 暂存”的部署策略。

本功能不改变 B200 计算参数，也不替实验选择 CPU、HOST DRAM 容量、暂存预算、并发度或 HBF 介质时序。对比实验仍需明确这些参数。

已用无 HBM、保留 CPU/HOST DRAM、固定 GPU 计算的双层重复 dense 模型验证 Prefill 和连续 Decode。该检查使用小规模合成形状与短时序，验证数据流、资源计费和完整页协议；不代表已完成 0.5B–70B 正式扫描或器件性能标定。
