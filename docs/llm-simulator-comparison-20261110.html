10 个核心术语（TTFT / TPOT · KV 缓存 · PD 分离 · TP / PP / EP · profile · HBM / HBF · tRCD / tPROG · FTL / GC）
TTFT / TPOT
请求到达后多久出第一个 token / 之后平均每个 token 的生成间隔。
KV 缓存
注意力层为每个请求保存的历史键值，随生成变长，占显存。
Prefill / Decode · PD 分离
先一次处理整段提示词，再逐 token 生成；PD 分离是把两步放到不同机器上。
TP / PP / EP
张量并行 / 流水线并行 / 专家并行：把一个模型切到多张卡上的三种方式。
profile（性能画像）
在真机上实测好的算子耗时表，仿真时查表或插值。
HBM
GPU 旁边堆叠的 DRAM 显存，按 bank 和行组织。
HBF
用 NAND 闪存堆叠成的高带宽存储，容量大，但写入（编程）慢。
tRCD
HBM 用 ACT 命令打开一行后，要等这么久才能读写；PRE 命令关闭该行。
tPROG
NAND 写入（编程）一页所需的时间，远长于读一页。
FTL / GC
闪存的地址映射层 / 垃圾回收：回收时要把有效页搬走再擦除整块。

第 1 步

先看结论：按要研究的问题选工具

没有一个工具能回答所有问题，不同仿真器分别聚焦服务调度、DRAM 命令、闪存管理或硬件互联。

本项目的位置 把服务调度、多卡并行和 HBM / HBF 器件时序放在同一条时间线上，覆盖面最宽；但尚无统一实机误差，HBM 只覆盖正常操作子集，HBF 也没有 FTL / GC。

各列判定口径

服务调度

连续批处理：请求一结束，空位马上由新请求补上，批的组成随之改变。

KV 容量：KV 缓存随生成增长、结束后释放；装不下时，新请求要等待或被抢占。

PD 分离：KV 从 Prefill 机读出、经链路传输、写入 Decode 机，三段都要计时。

多卡并行与互联

TP / PP / EP：模型按张量、流水段、专家切到多张卡，切法要进入计算和通信时间。

链路争用：多路数据同时走同一条链路时，要排队分带宽，而不是各按满带宽算。

内存器件

HBM 命令：逐条模拟开行、读写、关行和刷新，行命中与否改变时延。

NAND 时序：HBF 的页读、页编程、块擦除各自占用闪存阵列。

FTL / GC：垃圾回收搬运有效页产生的读写也要计时。

实测数据对齐

对齐状态：核心目标已对照真机并公布误差，或仅子层 / 训练 / 注入 / Verilog 局部对齐。

硬件 / 模型 / 分项误差：实际验证的硬件配置、模型负载与各指标误差；验证对象不同，不可横比。

●支持：已实现并经源码核实 ◐部分：有这条路径，缺关键环节 ✕不提供：属于它的研究范围，但没有这个机制 —不适用：不在它的设计范围内

✕ 和 — 的区别：✕ 是该做而没做，例如 HBF 仿真器没有 FTL / GC；— 是本来就不做，例如服务仿真器不模拟器件命令，DRAM 仿真器不处理 LLM 请求。服务类工具的器件列多是 —，但它们的结果里照样包含实测的内存耗时。
