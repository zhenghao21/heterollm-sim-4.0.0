# 仿真器独立优化流程

用户于 2026-10-01 确认使用本流程，替代旧优化循环的流程约束。目的是让每轮可复现地回答：修改了哪个机制、实际影响哪些场景、证据是否支持接纳、下一步为什么如此选择。

## 1. 目标和适用域

每轮明确主要目的：预测精度、仿真器工程质量或部署方案搜索。避免把目的不同的变更混进一个候选。声明模型、硬件、运行时、格式、shape、负载和输出策略；未验证范围保持未知。

### 1.1 方向组合与轮换

项目优化不是沿着第一个发现的缺口无限深挖，而是一个有方向预算的组合。每轮必须先登记一个 `direction`，并更新 `docs/OPTIMIZATION_DIRECTION_LEDGER.md`。至少维护以下七个方向：

1. **仿真器正确性与语义**：状态、调度、资源守恒、错误处理、报告契约和 API 行为。
2. **运行速度与内存**：仿真 wall time、峰值内存、图编译、缓存、批处理吞吐和开发反馈速度；必须区分仿真器自身开销与被模拟系统的预测结果。
3. **计算成本模型**：GEMM、归约、内存、链路、kernel、并发和调度成本公式，以及参数来源、单位和 shape 泛化。
4. **存储硬件建模粒度**：DRAM、HBM、NAND、SSD、HBF 的层级 geometry、page/plane/die/channel、访问并行、读写/擦除和内部队列；任务一和任务二见 `docs/STORAGE_MODELING_WORKPLAN.md`。
5. **预测精度与泛化**：与独立 Native 观测的成对误差、跨模型/硬件/shape 泛化；没有 Native 观测时只能记录机制一致性。
6. **评估、API 与可视化口径**：结果边界、评分、失败/缺失、序列化和 UI/文本显示的一致性。
7. **开发工具链与可复现性**：测试隔离、缓存身份、实验记录、基线配对、证据哈希和恢复能力。

轮换规则如下：同一方向最多连续两轮；第三轮只有在 `experiment.json` 中登记高影响阻塞、已验证触发面、方向收口清单和继续投入的理由时才能继续。一个方向的负向扫描只关闭该方向的当前假设，不能把项目标记为“没有可优化内容”。当某轮没有候选时，下一次发现工作必须切换到最近未检查或最长未检查的方向。每完成两轮正确性/语义工作，至少安排一轮运行速度或计算成本模型发现；若这两个方向连续两轮没有候选，也要保留实际测量和负结论，而不是回到正确性方向。

每轮汇报必须同时给出：本轮方向、最近三轮方向、各方向最后检查轮次、方向切换理由，以及本轮是否产生了运行速度、内存、成本模型或预测精度证据。单元测试通过只属于工程回归证据，不能替代速度或精度测量。

准备时声明主指标、保护指标、禁止退化规则、最小有意义改善、实验单位、噪声处理和预算。数值标准按问题制定，不自动继承历史门槛，不在看到结果后放宽。

## 2. 数据角色和比较版本

数据分为机制开发、候选比较、留出和最终验收。按模型、硬件、shape 或独立批次留出；相关 token/请求不能充当独立重复。已查看的比较数据不能重新称为盲测。

分别记录历史比较起点、当前开发基线和发布版本。候选与合法基线同输入成对运行；接受新基线不覆盖旧基线。版本发布不意味着模型验收通过。

## 3. 假设和实现

每轮选择一个可证伪的因果假设，说明原因、触发条件、受影响的工作量/资源、预期变化、控制项和否定条件。假设还必须说明属于哪个方向，以及它不会替代哪些尚未检查的方向。误差聚类帮助定位，不能单凭残差证明缺失成本。

问题域必须在同一轮收口：如果同一根因同时影响写入、读取、并发、错误处理、API 入口或回归行为，这些直接耦合的表面必须在本轮一起检查并修复，不能按调用点拆成多轮。只有独立根因、不同主要目标或预算无法覆盖时才允许拆分；拆分时在 `experiment.json` 和 `decision.json` 中记录边界、未覆盖项和拆分理由。

候选是该假设的最小完整修复，可以跨文件和层级。检查抽象、状态、owner、调度与计费；物理参数需独立来源。不得以目标模型端到端耗时拟合无解释倍率。

优先选择影响大、证据不确定但可取得、适用范围广且实现成本可控的假设。不存在必须先穷尽某一层才可查看其他层的通用规则；依赖和风险决定检查顺序。

## 4. 执行阶段

1. **prepare**：冻结目标、输入、数据角色、基线身份、比较方法和预算；屏蔽旧候选结论。准备阶段允许先诊断，再登记唯一候选。
2. **verify**：验证公式、shape、单位、容量、序列化和非法输入；补充触发、排除、控制场景；确认改动进入真实执行链路且模块身份正确。
3. **predict**：基线/候选独立进程预测，保存结果后才允许读取目标观测。源码或配置改变需新预测身份。
4. **score**：同一观测和聚合口径配对评分；保留失败/缺失/回退；比较逐格误差和机制激活。没有物理观测时可评估已知解析真值，但只能宣称对应机制一致性。
5. **review**：独立检查代码、实际执行、控制项、证据、覆盖和退化；必要时补最小证据，不重新运行已通过且未受影响的检查。
6. **promote**：按预登记规则接受、拒绝或保留证据不足状态。达到开发目标后才冻结进入独立验收；揭盲数据转回归数据。

每轮 promote 前执行问题域收口检查：列出该根因的写入、读取、并发、错误、API 和回归触发面；每一面标记为已修复、已验证无缺陷、明确不适用或有理由延期。未完成的同根因表面不能仅因为单个测试通过而进入下一轮。

阶段不要求六个新 CLI；复用现有测试、仿真 API 和评分函数。只有出现可证实的工具缺口才添加最小工具。

## 5. 评估要求

逐场景保留 TTFT/TPOT/E2E 的有符号误差、绝对毫秒误差和 APE，并报告改善/保持/退化、覆盖、回退和失败。中位数/P90/最大值用于解释，不能隐藏场景级退化。

统计单位是独立实验批次；同一运行内 token 或并发请求具有依赖。按预先指定方法处理噪声、独立性、采样量和多重比较，不反复抽样直到过线。单请求 E2E=TTFT+(N-1)*TPOT，三项不是三份独立证据。

合成算子精度、端到端精度、跨模型/硬件泛化分别报告。独立性能曲面仅适用于身份、kernel、cache 协议与联合 shape 合格的区域。

工程优化评价输出等价性、仿真 wall time 和峰值内存；准确性优化则评价系统行为和预测误差。正确的结构修复无数值收益时可保留，不冒充精度晋升；不能为较好分数恢复已知错误语义。

## 6. 决策和下一轮

- 代码/机制不安全：修复；没有激活：核查路径和触发域。
- 假设证伪：保留有限负结论，换假设。
- 结构正确但无改善：检查关键路径和覆盖，保留结构结果，不重复无变化评分。
- 改善但证据不足：补接纳所需的最小证据；明显退化：拒绝或显式限定支持域。
- 可靠改善且保护项通过：可以晋升开发基线；正式发布结论仍需独立验收。
- 预算耗尽、用户停止、身份/配对失效或环境不可用：保留检查点，停止受影响执行。

每轮完成时记录下一假设、下一方向及理由；自动执行仅在当前授权范围和预算内继续，不把一次第一轮授权扩展成无限优化。没有候选时，下一步应登记方向切换和发现预算，而不是重复同一方向的扫描。

## 7. 最小持久化记录

`experiments/<round_id>/` 中保留四个机器可读文件：

- `experiment.json`：目标、适用域、数据角色、输入和基线、评分规则、预算。
- `candidate.json`：假设、父版本、必要修改、候选源码身份、激活和测试记录。
- `evaluation.json`：预测/评分引用、实现/机制/预测/精度/泛化/回归状态、限制。
- `decision.json`：接纳决定、依据、基线是否晋升、剩余问题和下一步。

大量报告和日志保存在忽略的 artifacts 目录，四个记录只保留必要摘要、路径和哈希。阶段中可以更新工作记录；已经完成的预测与评分不覆盖。

## 8. 恢复工作

恢复时读取根 AGENTS、本流程和本轮四个记录，检查当前源码与已验证身份，确认是否有正在运行的进程，再从未完成阶段继续。不得因上下文丢失重置预算、重跑已完成实验或把未知写成通过。
