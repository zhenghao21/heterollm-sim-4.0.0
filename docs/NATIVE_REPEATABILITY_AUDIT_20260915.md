# Native 测量重复性审计与降波动（2026-09-15）

本轮只优化原生测量可信度与重复性，没有修改仿真成本模型。结论以固定确认批次的全部样本为准，旧失败、中断、慢样本和缺失均保留。**重复性偏差不是仿真预测误差；两项任务不能互相替代。**

## 判定合同

同模型、prompt、输出策略、并发、运行库、硬件控制条件下，以全部重复的中位数为中心计算每次有符号偏差。分别检查每批请求中位数，以及按 engine_request_begin_us 排序的每个请求rank，三项Engine TTFT/TPOT/E2E的最大绝对偏差均不超过5%、完整覆盖、至少两个独立进程，才算本次样本通过。

保留P90、最大偏差、绝对毫秒、±5%内比例、CV、失败和缺失分母。CV<5%、中位数置信区间窄、单个进程短筛查都不能替代该门禁。40次、两个进程的样本通过也不等于任意未来运行的保证。

## 根因证据与纠正

1. **预热没有覆盖正式工作。** 旧预热只有一批非流式请求、最多两个输出且允许EOS，Smol有42次、Tiny有21次只生成一个token。正式流式固定输出、并发的实际图和decode路径没有被完整预热。少数场景首轮TTFT约90ms，后两轮约6–8ms，与首次准备成本一致；无对应旧trace，不能把整个差额确定为CUDA graph创建。新方案同prompt、并发、流式与完整输出预热8批，并保存预热原始记录。

2. **关闭profiler没有消除注释开销。** CUDA NVTX scope即使无人采集仍检查layout、格式化字符串；host trace宏关闭但11处调用仍先构造标签。独立annotation-control runtime在开关关闭时先退出，避免这些工作。CUDA on/off对照通常改善GPU decode，但没有统一使TTFT达标；不能把它写成唯一根因。host标签在两个开关状态均编译去除，on/off只切换CUDA operator/fusion/phase。

3. **线程参数曾被错误解释。** 原CPU后端使用OpenMP，因此ggml原生poll不控制其等待方式；亲和性和优先级在OpenMP分支仍会应用。新non-OpenMP runtime仅换CPU DLL、重编16 CPU编译单元和2 PCH，其他runtime SHA不变。按实测CPU拓扑选择每个物理核一个逻辑CPU，实际查询线程mask；prefill/decode两套参数都显式设置。High优先级、高性能电源和单CCD没有统一收益，最终保留普通优先级。观察到16个单核mask不等于有独立worker TID语义证明。

4. **并发数不唯一决定实际执行批。** 独立HTTP即使同时发出，也可能在不同轮进入engine。实际拆批会改变shape、kernel路径和图重用；不按慢/快删除样本。原子prompt-list是不同的提交方式，已单独对照，不能冒充独立HTTP。cache_prompt=false也没有禁止LRU RAM缓存保存/加载；该路径在engine开始之前，影响入场与状态，不应直接塞入GPU成本。

5. **Engine首token仍含CPU与调度工作。** 起点是开始处理已就绪prompt，终点是首token完成sample/accept及相关同步；图准备、batch准备、部分cache/checkpoint行为和采样都可能在其中。它不是单纯CUDA kernel相加。CUDA Graph属性比较还包含地址、shape与stride，相同prompt长度和固定预热次数不能证明每次使用同一张图。禁用图的环境变量按“存在”判断，设为字符串0也会禁用；开启时应真正删除变量。

6. **硬件状态需要实际控制与核验。** GPU承担桌面显示，当前为WDDM。最初非管理员锁频被拒绝；随后使用已授权的管理员辅助进程，驱动接受锁频命令，恢复命令成功。固定确认请求2400MHz，启动后的真实读数2392MHz，前后按2400±30MHz核验。命令成功和少量快照都不能证明每个瞬间完全无调度干扰；不能仅凭使用WDDM就认定抢占是全部根因。

7. **中断暴露了证据持久化缺口。** 原runner只在整个进程块结束落盘。D2会话中断时，已完成的四个Qwen块保留，27B孤立日志没有可恢复raw。新的runner每批正常结束后在计时请求外追加不可覆盖的完整SSE/token journal；预热后、测量结束均核验状态；跨进程绑定同一份实际loaded runtime身份。失败、不完整与缺失不变成通过。

## Trace 分层证据的限制

已实际采集CUDA/NVTX/WDDM与CPU调度事件；含219025条SCHED记录、173286条CUDA kernel、173286次直接launch，cudaStreamSynchronize共9100次。同步API事件总耗时388.510ms、单次最大3.618ms只是API区间统计，不是GPU忙区间并集，不能直接加进engine时间。

锁定源码用`ubatch.n_tokens>1`选择prefill标签，并发decode同样满足它。本次242个phase范围中241个被标为prefill、1个decode；捕获内实际为6次warmup+8次测量，四批分裂接纳，14×17+4=242。必须结合真实shape和顺序还原，不能按该标签直接拟合prefill/decode成本。标签问题不等于原始engine token时刻或三指标公式错误。

采集器警告CUDA driver13.4不受当前Nsight2024.6完整支持，回退12.8收集库，且native进程有部分NVTX可能未采全提示。WDDM中153条preempted记录跨全部捕获上下文，不能称为native被抢占153次。TTFT最大的两个诊断批都拆分接纳，但另一个拆分批没有同等尾部，尚不能确定全部因果链。原始nsys-rep、SQLite、警告和身份均保留；本trace只支持受限诊断，不满足完整阶段标定证据要求。

## 新原生运行条件与确认范围

新runtime是annotation-control＋非OpenMP CPU后端。16物理核单线程mask、普通优先级，CPU-placement poll50、GPU-placement poll0；两侧prefill/decode设置一致。cache RAM为0、annotations为0、实际GPU目标2400MHz；KV、batch64/ubatch64、固定输出、temperature0、seed42、无推测解码等均冻结并保存实际命令。

一次冻结确认包含5模型×3场景×2独立进程×20正式批次，共30进程块、600批、1400请求；每进程先做8次同场景预热。短/中/长prompt分别搭配并发4/2/1，GPU模型输出17/49/97，27B输出均为4。只验证这些组合，不覆盖所有排列，也不覆盖27B长输出。

证据位于`../artifacts/development/native_repeatability_5pct/`。完整结果以`final_repeatability_report.json`和`.md`为准；本报告末尾在确认完成后回填。

原campaign的90分钟wall截止及会话中断事实保留，没有改写预算。恢复轮单独预先限定为一次线程筛查、一次trace、一次五模型确认，截止北京时间2026-09-15 13:57:09；不因未过线换样本或继续加样。任务执行中源文件冻结，结束核验后才允许修改；旧原始actual始终不覆盖。

两套新runtime尚没有新的正式计时等价证明，observer等价也未因此自动通过。后续比较仿真误差必须匹配新CPU后端、GPU频率、实际CPU资源和采集合同，不能套用旧profile并宣称新预测准确性已验收。
