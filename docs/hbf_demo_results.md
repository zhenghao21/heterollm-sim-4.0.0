# HBF 参数重跑结果

本次重跑使用 `nvidia-b200-1gpu-2hbf-2hbm`，HBF 登记参数为：读 488 GB/s、写 27.2 GB/s、读延迟 4 μs、写延迟 75 μs；GPU↔HBF 链路协议字段为 `HBF`，物理承载在 metadata 中记录为 UCIe。

模型使用离线目录中的 Qwen2.5 预设，候选构造与前端“KV Cache 分层扫描”一致：固定 HBM、固定 HBF、HBM 主缓存 + HBF 卸载。结果来自同一个事件仿真内核，按同一模型、同一负载和同一硬件逐候选运行。

## 现场解释

- 短上下文、低并发且 HBM 容量充足时，HBM-only 是当前 E2E 甜点；混合方案没有触发卸载，所以它和 HBM-only 相同。
- 在 Qwen2.5-0.5B 的中等批量场景里，HBF-only 的 E2E 比 HBM-only 高约 9.8%，说明写入延迟和读写方向带宽会在 KV 直接驻留 HBF 时体现出来。
- Qwen2.5-7B 的短场景被模型计算路径主导，三个候选的结果相同。这个结果本身说明甜点点位与模型规模有关，不能只根据介质带宽做结论。
- 真正需要混合方案发挥容量价值时，要选择长上下文、高并发或明确的 HBM 容量压力坐标，并在结果页确认 `Migration`、`Offload` 和 `Swap Transfer` 大于零。没有发生迁移时，混合方案只是 HBM-only 的等价策略。

这些结果是 `ANALYTICAL` 分析仿真，不是 HBF 芯片实测；本次 HBF 数值是用户指定的可替换参数。前端仍会按 Profile 字段、链路可达性和容量约束进行校验。
