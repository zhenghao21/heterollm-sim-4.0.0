## 2026-10-17：可选快速仿真模式

详细模式保持默认，继续完整执行每个 Token 和物理事务。新增 `simulation.mode="fast"`，只在明确选择时使用近似 Decode；正式扫描及自动跟进继续暂停。此功能与 `exact/streaming/aggregate` 结果保留策略独立，不能用 aggregate 表示近似计算。

  "fast_decode": {

Prefill 和首个可见 Token 仍详细执行，因此 TTFT 来自原内核。当前开发候选默认按上表自适应选择 Decode 采样窗口；指定 `sampling_strategy="fixed"` 使用原 8 / 32 / 16 初始窗口，预测公式不变，但采用新增维护与比值安全检查，可能更严格地转为详细执行。窗口不稳定时继续采样，最多 128 步。采样使用原始完整输出预算，保留真实的 KV 地址、容量预留与控制器状态，不通过缩短请求取样。短输出、校准不稳定或超出适用范围时，从同一个运行时继续详细执行。

尾段按上下文分段预测平均耗时。短窗口无法可靠识别 64K 上下文下很小的斜率，首版采用研究假设 `T(L)=A+B·L，A≥0、B≥0` 的常量端点与正比增长端点，以其相对误差平衡中点估算，避免把数值噪声外推成长请求的巨大斜率。上下文增长上限为 20%；这个区间是**条件模型包络，不是硬件性能上下界、统计置信区间或全局 10% 保证**。前缀留出检查不能代替完整请求对照。

## 2026-10-17：Token 执行流程重构

正式扫描及其自动跟进继续暂停。本次以已经修正为 256 bank、每通道独立准入队列的版本为起点，不使用旧几何的速度作基线。实现与测量记录位于 `artifacts/token_native_20261017`；这些是性能诊断，不是正式扫描结果。

本次将完整 Token 的依赖关系编译为整数位置图，在当前 Token 绑定任务标识、请求归属、资源需求和释放时间。调度使用同一持久资源日历，逐任务提交真实控制器事务；保留异常回滚、取消、公开观察回调、动态追加任务及内存回收边界。HBF 的预览和实际执行分别保留各自原有的记录与统计。

普通单 GPU、单请求 BF16 Decode 还可复用整模型任务图。KV 和 attention emitter 显式声明随上下文变化的存储及工作量字段，每个 Token 重新计算容量、读写范围、追加地址、请求 generation 和当前 cost。它不复用上一个 Token 的物理完成时间。未覆盖的布局或执行族仍由同一编译器正常生成；形状、fusion 或 phase 数量变化时重新生成。已知会被当前公式完整覆盖的旧内置容器不再先复制再丢弃；其余描述符、路由、别名和自定义复制协议保持原边界，没有扩大对象共享范围。

物理执行先验证整项任务的访问描述，再提交有序指令。HBF 直接把 HOST、NAND 和链路的真实事务交给任务账本，减少中间逻辑事务包装；原 HOST 接收与 NAND 落盘的完成边界保留。只复制原实现要求独立拥有的描述符与路由容器，硬件配置仍按原边界共享。

曾尝试 NAND 连续 READ 的严格周期执行，逐页输出与状态对照通过，同一候选状态机开关的连续 16,384 页微测约 5.47–5.49×。但直接与重构起点比较时，常用的未命中条带路径反而慢了约 28%–31%：9 bank／2130 页由 0.813 增至 1.061 ms，55 bank／16384 页由 6.247 增至 8.020 ms。KV 读使用的逐页 arrival 向量也未满足该候选的标量 arrival 条件。因此已完整撤销周期代码，最终实现逐页执行原控制器，其数值循环与重构起点一致；受影响 HOST 队列的归约放在循环外的编译辅助函数中。最终版本不包含上述周期执行的微测收益。

最终统一回归覆盖 33 份去重测试文件，**502 项通过，耗时 58.27 秒**；没有把先前多轮重叠测试数量相加。覆盖 Token 回调、动态追加／取消、事件预算、源代码与编译版本、整模型绑定边界、metadata 别名与自定义复制、物理账本、HOST staging、NAND 准入与状态、完整结果比较和事务捕获。数值控制器还对照全部返回字段及状态数组，没有放宽断言。收尾确认扫描进程为零、自动跟进为 PAUSED，旧正式扫描历史目录未重建。

## 慢在哪里

大块访存主要消耗在逐 burst 的命令计算。当前实验每个 burst 为 32 字节，128 MiB 访问需要处理 4,194,304 个 burst；70B 模型仅一次完整 BF16 权重读取就约为 131.414 GiB。因此即使只生成几个 token，命令数也很大。512 GiB 工作点的一次 128 MiB 读诊断中，数值执行核约占总时间的 97%，已经启用 Numba 编译执行，并非退回 Python 逐条解释。

小请求和完整推理还会反复整理、保存控制器状态。该工作点有 16,384 个 bank 和 256 个 pseudo-channel。原来每次提交都会重建资源名称，并将所有已有 bank 写回；运行时保存状态还会重复调用通用深复制。Small 完整推理的诊断共发生 113 次数值执行入口调用、152 次运行时状态保存，时间较多地花在这些外围操作上。

## 已实施的修改

1. 数值核心在维护检查完成、当前行仍命中时，复用刚计算出的列命令时间。每个请求固定的恢复时间只计算一次。仍逐条处理所有 burst，保留 float64、时钟对齐顺序和 `fastmath=False`。
2. 按几何和资源前缀缓存不可变的资源名称及索引。每次请求仍读取当前控制器、资源别名和时间线状态；缓存不保存可变控制器状态。
3. 使用数组精确比较找出变化的 bank/channel，仅写回这些项目。浮点比较包含正负零差异；刷新影响到的其他 bank 同样写回。所有已出现 pseudo-channel 的嵌套历史仍按原方式重建，保留扩展字段引用行为。
4. 对普通字典、列表和标量历史使用专用复制路径；保留循环、共享引用和自定义对象的深复制协议及 memo 替换行为。请求失败和批量前缀的恢复逻辑保持原样。

没有调整请求顺序、批量边界、刷新次数、地址映射、模型尺寸或时序参数，也没有使用抽样、跳过命令、低精度计算或分析带宽公式替代命令执行。
