## 2026-10-18：第 100 块后 GC 耗时分解与回滚优化

按用户新指令暂停正式队列和自动跟进；1.5B HBF / 256K / 1K 在第 107 个 Prefill 块后取消，27 个已成功配置及四点配对验收结果保留，没有重跑完整详细参考。上一轮只测空 victim，漏掉了需要搬运活页时的回退成本。本轮使用正式 256-bank、524,288-block 几何及真实 NAND/HOST/链路回调，直接建立已编程控制器状态，分别测空 victim 和带约 104 万保留页、读取缓存的 live-copy GC，避免再重放完整长输入作为详细参考。

根因是大写的空 GC 试探发现 victim 还有活页后，整批撤销并转回原逐页路径。原回滚即使没有改动任何页，也会遍历全部 KV 页、拆掉读取缓存，并丢弃回收索引；随后又重建这些派生数据。带性能分析器的旧版 8 笔、每笔 256 页负载耗时 21.2335 秒，其互不重叠的主要边界如下；其中 `_touch_page_ready` 已计入回滚，不能重复相加。

| --- | ---: | ---: |
| 回滚恢复及全量 KV 读缓存拆除 | 12.5275 s | 59.00% |
| 重新建立密集读取缓存 | 5.0003 s | 23.55% |
| victim 查找与回收索引重建 | 3.2241 s | 15.18% |
| NAND 页执行代码 | 0.1787 s | 0.84% |

## 2026-10-17：可选快速仿真模式

Prefill 和首个可见 Token 仍详细执行，因此 TTFT 来自原内核。当前开发候选默认按上表自适应选择 Decode 采样窗口；指定 `sampling_strategy="fixed"` 使用原 8 / 32 / 16 初始窗口，预测公式不变，但采用新增维护与比值安全检查，可能更严格地转为详细执行。窗口不稳定时继续采样，最多 128 步。采样使用原始完整输出预算，保留真实的 KV 地址、容量预留与控制器状态，不通过缩短请求取样。短输出、校准不稳定或超出适用范围时，从同一个运行时继续详细执行。

尾段按上下文分段预测平均耗时。短窗口无法可靠识别 64K 上下文下很小的斜率，首版采用研究假设 `T(L)=A+B·L，A≥0、B≥0` 的常量端点与正比增长端点，以其相对误差平衡中点估算，避免把数值噪声外推成长请求的巨大斜率。上下文增长上限为 20%；这个区间是**条件模型包络，不是硬件性能上下界、统计置信区间或全局 10% 保证**。前缀留出检查不能代替完整请求对照。

HBM 状态刷新另做了同源码编译辅助函数候选：保留每次读取公开 timeline、别名和异常协议，合并内置 calendar 的长度与身份检查，减少临时容器；没有改变控制器数值循环。40 组严格状态／异常顺序对照及 93 项相关测试通过，刷新函数微测约 **1.035～1.245×**。但 0.5B、32 输入／33 输出完整 A/B/B/A 的两配对仅为 **0.9542×、1.0138×**，合并 **0.9832×**，无法取得稳定整步收益；旧版自身波动 0.86%、候选波动 5.34%。四份仿真结果精确相同，但不能以局部微测替代整体结论，因此已撤销候选、删除专属测试并强制重建扩展。两个相关源码文件与本轮起点逐字节相同，79 项恢复后的相关测试通过。见 [刷新函数微测](../artifacts/decode_bottleneck_20261017/hbm_refresh_micro.json)、[完整 Decode 对照](../artifacts/decode_bottleneck_20261017/abba_HBM_comparison.json)。

六个诊断点的完整仿真字段均有同配置未插桩结果严格对照，未放宽未知字段、浮点值或 cohort 顺序。正式扫描和自动跟进保持暂停。

进一步针对 7B HBF 页映射做细分后，排除了泛化重写 staging 的必要：后续 7 步中，791 次 `np.maximum.at` 累计约 832.6 ms，约 **118.94 ms/步、6.93%**；它负责按 block 归并逐页完成时间。`block_ready.update_max` 仅约 0.23%、`np.full` 约 0.03%、计划缓存查找约 0.02%，其余完整页函数本体约 0.10%。本次细分使用只作用于 `hbf_staging` 的 NumPy facade，未修改 Numba 模块；完整结果与此前 7B 对照精确相同。记录见 `page_detail_7b_HBF_P32_D9_profile.json`。

据此仅替换该归并调用：同源码 Cython helper 按原输入顺序取最大值，有限值相等时保存后一个操作数，保留正负零。整数位检查在首次写入前识别非有限值，不提前改变 signalling NaN；别名、广播、子类、只读、非本机 dtype、越界等协议交给同一 NumPy ufunc，保持原异常与部分写入行为。没有扩展时直接执行 ufunc，避免 Python 逐元素循环变慢。159 项定向检查通过。

真实 7B Decode 的 5 种形状、113 次／步原语微测约 15.5～27.2×；完整阶段复核中，页映射与状态项由 **125.97 降至 12.08 ms/步，约 10.43×**，全部仿真字段精确相同。原语微测与插桩时间都不作为端到端速度结论。首轮独立进程 A/B/B/A 的起点自身漂移约 15%，大于目标约 7% 的整步收益，不能据此接受或拒绝候选。随后改用同一进程、同一二进制、固定逻辑 CPU、预热后的完整请求配对；A 临时将这一函数指向原 `np.maximum.at`，B 使用编译 helper，不增加仿真器运行时选项。

最终 7B HBF、32 输入／17 输出受控实验固定本进程逻辑 CPU 2（mask `0x4`），先用同模型 32／9 完整请求预热，再按 A/B/B/A 各执行完整请求，之间回收前次请求对象。四份完整仿真结果精确相同。两组 Decode 配对为 **1.0385×、1.0637×**，合并 **1.0511×**；每步均值旧版 1.7701／1.8183 秒，新版 1.7045／1.7094 秒。排除各自首步后，两配对为 1.0431×／1.0619×，合并 1.0525×；旧版自身后续步波动 1.90%、新版 0.094%，两组改善均超过各自波动。这个受控结果只说明该工作点的完整 Decode 约快 5%，不与未绑核的其他测量合并，也不意味着整个扫描快 10 倍或 100 倍。生产只保留这一小范围归并优化。见 [受控端到端对照](../artifacts/decode_bottleneck_20261017/controlled_indexed_max_7b_HBF_comparison.json)。

## 2026-10-17：Token 执行流程重构

正式扫描及其自动跟进继续暂停。本次以已经修正为 256 bank、每通道独立准入队列的版本为起点，不使用旧几何的速度作基线。实现与测量记录位于 `artifacts/token_native_20261017`；这些是性能诊断，不是正式扫描结果。

本次将完整 Token 的依赖关系编译为整数位置图，在当前 Token 绑定任务标识、请求归属、资源需求和释放时间。调度使用同一持久资源日历，逐任务提交真实控制器事务；保留异常回滚、取消、公开观察回调、动态追加任务及内存回收边界。HBF 的预览和实际执行分别保留各自原有的记录与统计。

普通单 GPU、单请求 BF16 Decode 还可复用整模型任务图。KV 和 attention emitter 显式声明随上下文变化的存储及工作量字段，每个 Token 重新计算容量、读写范围、追加地址、请求 generation 和当前 cost。它不复用上一个 Token 的物理完成时间。未覆盖的布局或执行族仍由同一编译器正常生成；形状、fusion 或 phase 数量变化时重新生成。已知会被当前公式完整覆盖的旧内置容器不再先复制再丢弃；其余描述符、路由、别名和自定义复制协议保持原边界，没有扩大对象共享范围。

物理执行先验证整项任务的访问描述，再提交有序指令。HBF 直接把 HOST、NAND 和链路的真实事务交给任务账本，减少中间逻辑事务包装；原 HOST 接收与 NAND 落盘的完成边界保留。只复制原实现要求独立拥有的描述符与路由容器，硬件配置仍按原边界共享。

曾尝试 NAND 连续 READ 的严格周期执行，逐页输出与状态对照通过，同一候选状态机开关的连续 16,384 页微测约 5.47–5.49×。但直接与重构起点比较时，常用的未命中条带路径反而慢了约 28%–31%：9 bank／2130 页由 0.813 增至 1.061 ms，55 bank／16384 页由 6.247 增至 8.020 ms。KV 读使用的逐页 arrival 向量也未满足该候选的标量 arrival 条件。因此已完整撤销周期代码，最终实现逐页执行原控制器，其数值循环与重构起点一致；受影响 HOST 队列的归约放在循环外的编译辅助函数中。最终版本不包含上述周期执行的微测收益。

**本轮没有达到 100×。** 最终版本的代表点如下，表中是电脑实际运行的 Decode 耗时，不是模型预测 TPOT；各点全部仿真字段均严格相同，没有数值容差。

本次重构贯通任务图绑定、调度、物理提交和统计，但没有把全部数据都变为无 Python 对象的常驻数组程序。当前任务需求、公开 metadata、物理结果及观察记录仍按原语义生成，控制器仍执行逐页／逐 burst 状态转换。任务图复用只消除了部分工作，首次建立整模型任务图还会增加一次性开销，短输出请求可能更慢。因此不能把此次改动描述成所有工作点均有收益，也不能据此承诺百倍缩短扫描工期。

完整 DAG 的边界对照覆盖 HBM/HBF、0.5B/7B、31/32/33 上下文、4 KiB KV 边界、64/96 请求预算及相同 context 下不同 history，逐字段比较类型、浮点位值和字典顺序。32 输入/9 输出的完整有序物理记录中，HBM 12,753 条、HBF 21,524 条事务均与起点逐条精确相同，包括 HOST scope 内执行、NAND 页完成数组及账单；捕获额外开销不参与速度比较。HBF 基线使用同一捕获器重新采集，补齐初版捕获器漏记的 HOST scope 请求，没有过滤新版多出的记录来迎合旧捕获结果。

最终统一回归覆盖 33 份去重测试文件，**502 项通过，耗时 58.27 秒**；没有把先前多轮重叠测试数量相加。覆盖 Token 回调、动态追加／取消、事件预算、源代码与编译版本、整模型绑定边界、metadata 别名与自定义复制、物理账本、HOST staging、NAND 准入与状态、完整结果比较和事务捕获。数值控制器还对照全部返回字段及状态数组，没有放宽断言。收尾确认扫描进程为零、自动跟进为 PAUSED，旧正式扫描历史目录未重建。

本轮优化减少仿真器自身的计算和状态处理开销。模型、硬件参数、每条内存命令的执行规则和预测精度保持原样。性能测量和等价检查见 [本轮结果](../artifacts/hbm_execution_performance_20261015/report.md)。

## 慢在哪里

大块访存主要消耗在逐 burst 的命令计算。当前实验每个 burst 为 32 字节，128 MiB 访问需要处理 4,194,304 个 burst；70B 模型仅一次完整 BF16 权重读取就约为 131.414 GiB。因此即使只生成几个 token，命令数也很大。512 GiB 工作点的一次 128 MiB 读诊断中，数值执行核约占总时间的 97%，已经启用 Numba 编译执行，并非退回 Python 逐条解释。

小请求和完整推理还会反复整理、保存控制器状态。该工作点有 16,384 个 bank 和 256 个 pseudo-channel。原来每次提交都会重建资源名称，并将所有已有 bank 写回；运行时保存状态还会重复调用通用深复制。Small 完整推理的诊断共发生 113 次数值执行入口调用、152 次运行时状态保存，时间较多地花在这些外围操作上。

## 已实施的修改

1. 数值核心在维护检查完成、当前行仍命中时，复用刚计算出的列命令时间。每个请求固定的恢复时间只计算一次。仍逐条处理所有 burst，保留 float64、时钟对齐顺序和 `fastmath=False`。
2. 按几何和资源前缀缓存不可变的资源名称及索引。每次请求仍读取当前控制器、资源别名和时间线状态；缓存不保存可变控制器状态。
3. 使用数组精确比较找出变化的 bank/channel，仅写回这些项目。浮点比较包含正负零差异；刷新影响到的其他 bank 同样写回。所有已出现 pseudo-channel 的嵌套历史仍按原方式重建，保留扩展字段引用行为。
4. 对普通字典、列表和标量历史使用专用复制路径；保留循环、共享引用和自定义对象的深复制协议及 memo 替换行为。请求失败和批量前缀的恢复逻辑保持原样。

没有调整请求顺序、批量边界、刷新次数、地址映射、模型尺寸或时序参数，也没有使用抽样、跳过命令、低精度计算或分析带宽公式替代命令执行。

## 验证方法

完整推理基准使用 Small、输入 128 token、批量 1、输出 4 token，覆盖 reference/ramulator2 两套参数与 A 全 HBM/B 的 KV 使用 HBF 两种放置，每组重复三次。优化前后分别在独立进程加载，均先预热编译器，比较完整返回数据，仅排除仿真器实际运行耗时字段。预测 TTFT、TPOT、吞吐、命令计数、资源统计和执行检查均参与比较。

数值核心另有 128 MiB 连续读写、同 bank 换行和多配置续接对照，逐请求结果及全部 14 个数组均作无容差比较。回归覆盖命令时序、刷新、tFAW、非二进制时钟、调度、异常恢复、扩展引用及运行时保存/恢复。

上述第一轮测量期间，原来的八个大模型实验仍在运行，故耗时是本机有其他负载时的测量。局部数值核和 Small 完整流程的加速倍数分别报告；没有将它们直接当作 70B/235B 完整仿真的加速倍数。

随后按用户要求停止旧八进程，仅重跑 70B 的四个对照点并加入进度监控，见 [70B 运行记录](../artifacts/hbm_70b_optimized_20261015/README.md)。进一步尝试的 deadline 增量维护、历史时钟缓存、时钟除法合并及 ACT 时间复用，未能同时满足完整语义和真实大请求的性能要求，均未保留。当前正式核心保留上文四项第一轮优化。

70B 四点现已全部完成，单点实际耗时约 208–221 分钟，最终数值核心占实际耗时约 89.3%–89.7%。完整预测、执行检查与结果边界见 [70B 最终报告](../artifacts/hbm_70b_optimized_20261015/report.md)。旧 70B 任务没有完整基线结果，因此仍不声称测得 70B 完整流程的加速倍数。
