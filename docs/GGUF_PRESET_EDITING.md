# GGUF 模型预设与参数编辑

前端可运行的模型预设由 GGUF 张量目录构建，与直接 GGUF 导入使用同一个后端构图器。预设包只保存结构和张量信息，不包含权重数据。

## 使用方法

1. 打开“模型 → 模型预设”。已绑定 GGUF 的条目显示实际权重格式，可以应用。
2. 点击条目上的“编辑并另存”，或应用后点击“编辑参数 / 另存预设”。
3. 修改层数、隐藏维度、前馈维度、注意力头数、KV 头数、头维度、词表大小、最大上下文或矩阵权重量化。
4. 点击“校验修改”。后端按架构和量化块重建张量形状及存储大小；不兼容的修改会显示原因。
5. 点击“另存新预设并应用”。原预设保留，新预设写入本地目录，服务重启后仍可加载。

参数编辑作用于仿真的文本主干，不改写 GGUF 权重文件，也不生成可以直接用于 native 推理的新权重。Qwen3.5 的线性注意力状态几何保留来源配置；本编辑器的注意力头参数用于全注意力层。额外 MTP 分支不在此编辑器的主干范围内。

修改过的模型标记为“基于 GGUF 修改”，保留来源和修改项，不能再用原 GGUF 的 native 结果直接代表它的预测精度。应用模型时清除旧模型映射及模型相关的 CUDA Graph 结构绑定；若保留开启 Graph 的运行设置，需要重新生成对应绑定后运行。

Llama 3.1 405B 使用该固定版本 GGUF 的 **16 KV 头**布局，名称标注 `Instruct (KV16)`。它与旧公开配置条目的 8 KV 头版本不同；元数据和 K/V 权重形状共同验证 16 KV 头，不重写为 8。官方型号定义也区分 MP8 与 MP16 变体。

Qwen3-30B-A3B 与 Qwen3-235B-A22B 的实际架构为 `qwen3moe`，显示“已有 GGUF，架构待适配”。前后端均禁止应用和参数编辑；本任务未实现 MoE 内核。

未来没有来源的条目仍显示“待补齐 GGUF”，不能应用。可以点击“绑定本机 GGUF”输入对应文件路径。绑定会核对架构、层数、词表及主要维度；不能把别的规模模型绑定到同名条目。目录缺片或结构校验失败同样禁用，不能转向配置估算路径。

## 分片与来源读取

新增来源固定 Hugging Face 仓库版本，记录实际文件、文件大小、发布者的 LFS 文件身份和量化。远程读取只保留头部、元数据和完整张量目录；采用 HTTP Range，要求 206 响应、准确的范围/长度/总大小，拒绝服务器返回整文件的回退。单次预读最多 256 KiB，末次预读可能包含少量未保存的权重字节；未下载整份权重，也未重新计算远程文件的完整哈希。

Llama 405B 的 6 个分片与 Qwen3 235B 的 5 个分片均已读全。分片编号、总片数、总张量数、重复张量、重复元数据及每片文件边界均校验。每个张量保留所属文件和物理偏移，跨文件相同偏移不再被当作同一权重。多片模型保留每片身份，不生成虚构的单文件 SHA。

本机直接 GGUF 导入使用相同目录解析和合并逻辑，指定任一规范命名分片时会读取同目录的全部分片；缺片即拒绝。多片的旧单文件缓存路径明确拒绝，需直接读取完整分片组。参数编辑生成新的虚拟张量目录，清除原分片偏移绑定，原始来源保存在派生预设的来源字段。

“从本机 GGUF 新建预设”可添加其他文件。尚未有可执行适配的架构会明确报错；在线 Hugging Face 配置导入只能创建待补齐条目，不能替代真实 GGUF 张量目录。

本地预设使用既有模型目录位置（可通过 `HETEROLLM_SIM_CATALOG_CACHE` 指定）。新增/派生预设以独立 ID 保存，保存失败不会覆盖原预设。
