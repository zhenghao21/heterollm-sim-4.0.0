# CUDA Graph 独立成本测量边界

本次运行在 RTX 5080、Ryzen 9 9950X3D、Windows 11、驱动 617.14、CUDA runtime 12.8 上。

## 两类数据

- `runtime_microbench_v2.json` / `runtime_calibration_v2.json`：普通链和四分支链的规模插值探索，训练/留出大小分开。全域生命周期预测**未合格**，最大留出误差约 1512.7%，主要来自 Windows 首次 Graph 启动非线性。不得将它标为合格成本。该早期探索的 capture 计时含节点数量查询，driver 字段为 CUDA 驱动 API 版本而非发行版本；这些边界问题在后续测量程序中已修正，后续实验使用下面的数据。
- `runtime_typed_chain_measurements.json`：对五个模型的 capture-only 结构编译结果提取 13 种唯一的节点/边组合，使用独立的小 CUDA 计算核和合成 D2D 拷贝，逐个重复测量。没有加载模型、模型参数或使用模型延迟。这是**结构精确匹配的实验成本**，没有声称通过独立泛化留出验证。

## 结构与计时

保留节点顺序、kernel/memcpy 类型、普通/程序化依赖边、D2D 拷贝字节数。捕获完成后，在计时之外重新枚举节点和边，验证生成图与结构模板一致。kernel 函数、启动几何、参数大小及共享内存仍然是合成值，因此真实 kernel 的 CPU API 提交成本可能不同。

每次独立测量遵循：普通提交；捕获；实例化；对刚实例化的同一张图执行 update；首次 launch；稳定 replay；销毁。stream/event 创建和结构核对均在对应计时之外。CPU 计时与 CUDA event 区间分别保存；event 区间用于诊断，不能用它替换仿真中的 GPU 计算和 DRAM 物理成本。

每个阶段保存全部重复值以及 median、MAD、minimum、maximum。MAD 是相对中位数的绝对偏差中位数，用于描述波动。最小/最大值是观察到的范围，不是统计置信区间。

最终结构实验使用 99 次重复。更新失败另按源码结构推导的旧→新图配对测量：533→425、729→594、937→762、2372→1956 节点，分别得到 1.2、1.3、2.3、6.8µs 中位数；每对也保存 99 次原始值。这些失败由节点数量改变确定，不使用 native 观测决策作为输入。销毁旧 Graph 和旧 executable 则使用旧结构对应的成本。不能把成功 update 的数字当成失败 update。

四类 decode 图的稳定 replay 中位数/MAD 分别是：425 节点 1.7/0.3µs、594 节点 1.7/0.2µs、762 节点 2.0/0.4µs、1956 节点 3.0/0.8µs。这些是独立 CPU API 提交测量，不是模型端到端误差。最后一次采样在其他任务确认空闲后独占执行，北京时间 2026-10-08 11:01:42.459622 至 11:02:01.186139；每个结构和配对保存 UTC 起止时刻。保留全部波动数据和实验未合格标记，不能宣称已达到泛化精度要求。

## 使用限制

生产默认 `runtime_measurement_mode=qualified`。只有训练区间内存在独立留出点并通过相应阶段门槛，才能调用正式成本。默认相对门槛 20%；噪声容差有固定上限 1µs，过宽波动不会自行获得资格。反序列化会从训练点和重复测量重新计算所有误差及资格。

实验必须显式设置 `runtime_measurement_mode=experimental_exact_structure`。此路径只接受已测的完整 typed topology 和节点数，不插值、不外推，也不回退到普通链。任务记录保留 `prediction_qualified=false`、重复测量范围和限制说明。未测阶段、复制类型或依赖类型会拒绝执行。

累计 host 服务量可按仿真预测的事件次数乘以各阶段 median 求和，并以 minimum/maximum 给出敏感性范围。由于 CPU 提交与 GPU 工作可能重叠，此范围不能直接相加到端到端耗时；端到端敏感性需要在同一任务依赖图上重新计算。
