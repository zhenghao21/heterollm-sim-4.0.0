# HBM 数值核心等价优化

仅删除重复计算，保持逐 burst 的完整命令执行。最终命中已打开行且维护检查完成时，复用同一状态上刚算出的列命令开始时间；换行和首次激活仍执行原来的重新计算。每次请求固定的恢复时间移到请求循环外，保留空范围行为。未修改 float64、时钟算法、任何计数或状态布局。

正式工作点为 `hbm3e_timing_reference`，512 GiB，CK=0.625 ns，读写方向预算各 1600 GB/s，物理接口 6553.6 GB/s，REFab 开启。双方先完成 JIT 预热，每项测量 6 次并交替运行顺序，取中位数。数组复制和编译不计入数值核心时间。原来的 8 个大模型仿真始终继续运行，因此这是同时有其他负载时的局部测量，不代表完整模型的总加速倍数。

| 场景 | 优化前 / 秒 | 优化后 / 秒 | 加速倍数 |
| --- | ---: | ---: | ---: |
| 128 MiB 冷态读 | 1.669 | 1.434 | 1.164× |
| 128 MiB 续接读 | 1.636 | 1.420 | 1.152× |
| 128 MiB 冷态写 | 1.724 | 1.473 | 1.171× |
| 128 MiB 续接写 | 1.728 | 1.452 | 1.190× |
| 同 bank 两行交替，65,536 次请求 | 0.790 | 0.719 | 1.099× |

`benchmark.json` 保存每次墙钟时间和进程 CPU 时间，以及每项行命中、未命中、冲突次数。短的 2,048 次换行试跑已被 65,536 次结果替换，以减少短计时误差。早期基础预设、未开启刷新或未固定 .625 ns 的试跑数据不用于此表。

等价检查：

- 每次测量逐请求比较完成时间、命中/未命中/冲突、全部命令计数；全部 14 个控制器数组用精确相等检查，无容差。
- 临时旧源码与最终数值核心另做 12 种配置的续接请求对照：CK=.625/.7/1 ns、两种地址映射、刷新开关、非零 FAW 和短 tRASmax。899 次成功请求完全相同；61 次原实现拒绝的请求保留相同异常与数组状态；24 对时钟溢出边界保留相同异常。
- 74 个正式回归通过，覆盖 HBM2E/3E/4、非二进制时钟、维护、端口争用、两种映射、FAW、批量续接和溢出回退；本次新增其中 8 个行命中与维护交叉边界用例。

复现局部性能测量：

```powershell
.venv/Scripts/python.exe scripts/benchmark_hbm_numeric.py --mib 128 --repetitions 6
```

如需在同一进程对照之前的源码，使用 `--baseline-source <临时旧模块路径>`；脚本会比较每次请求和全部数组。旧实现仅作本次诊断输入，不加入产品或作为运行时回退。

正式回归命令：

```powershell
.venv/Scripts/python.exe -m pytest tests/test_hbm_compiled_control.py tests/test_hbm_compiled_faw.py tests/test_hbm_numeric_row_hit_reuse.py -q
```
