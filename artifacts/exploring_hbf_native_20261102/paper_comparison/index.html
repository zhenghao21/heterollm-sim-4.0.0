结论

  1. 相对趋势和排序与论文一致，比上一轮更接近。以 8-GPU HBM4 为 1 的归一化每 GPU 吞吐，24 个非 HBM4 点 native/论文的几何平均为 0.99×（上一轮 1.15×），平均差 −0.01（+0.10），18/24 点差值在 ±0.15 以内（16/24）；6 组×10 对配置的相对排序 56/60 对一致（55/60）。HBF、HBF+ 与 HBM4 同一档（native 0.58–1.41，论文 0.76–1.29），CONV、CONV+ 明显落后（native 0.15–0.27，论文 0.16–0.29），这一主结论两边相同。
  2. 4 对排序不一致。Maverick SHORT 的 HBF+ 低于 HBF（0.58 vs 0.66，论文 0.98 vs 0.89），Maverick MID 的 HBF+ 低于 HBM4（0.97 vs 1.00，论文 1.19 vs 1.00），原因见第 3 条。405B SHORT 的 HBF+ 高于 HBM4（1.16 vs 1.00，论文 0.98 vs 1.00），论文接近平局，而 native 的 HBM4 在这里选了 DP2/TP4。Maverick MID 的 CONV 高于 CONV+（0.21 vs 0.18，论文 0.16 vs 0.20），差值小，CONV+ 带宽利用率已到 0.86，这一对没有单独定位。
  3. 最大偏差在 Maverick SHORT/MID 的 HBF/HBF+，native 都低于论文。超出 ±0.15 的 6 个点（论文/native）：Maverick SHORT HBF+ 0.98/0.58、SHORT HBF 0.89/0.66、MID HBF+ 1.19/0.97、MID HBF 1.00/0.81；另有 405B LONG HBF 1.08/1.28、405B SHORT HBF+ 0.98/1.16 偏高。上一轮的 405B SHORT HBF+ 异常（0.70）已消失，那是 KV 地址混叠，已由多 rank 分页 KV 解决。查过的三个点：
    • Maverick SHORT HBF+（EP8）：B3088 为 55.5 ms、吞吐 6958；B4096 为 80.8 ms，吞吐反降到 6339；更大的点因区间过宽未被接受（B6048 估计 7541，TPOT 82.9–126.9 ms）。what-if 拆分（B6048，非扫描结果）：当前配置 100.26 ms（吞吐 7541）；SRAM 放得下全部尾块 86.27 ms（8763）；KV 每请求一块 68.91 ms（10971）；两者都改 59.06 ms（12801，归一化 1.06）；再把页编程时间压到接近 0（此项在 256 token 块上测）47.06 ms（16064，纯计算受限）。机制是时间线上直接看到的：100 µs 的页编程没有挂起，会阻塞同 plane 上的读。256 token 块的尾页落点近似随机，一层内同一 plane 最多堆 4 次编程（下一层的读等 300–400 µs）；溢出时这些编程进入关键路径，kv_materialize 为 507–607 µs；每请求一块时只有 2 次。主机命令额度放大 100 倍，TPOT 不变。
    • Maverick MID HBF+（EP8）：B1504 为 49.9 ms；到 B1672，PD 导入多出 20.5–49 ms，TPOT 区间拉宽到 74–102.6 ms，估计吞吐也不再增长。论文的 Prefill 节点理想，没有这项开销。
    • Maverick MID HBF（EP8）：B2776 为 106 ms 未通过，再插值约 B2604，与它不足一个搜索步长，于是停在通过端 B1648（65.5 ms）。吞吐只低约 4%，但 batch 明显被低估。
    Maverick SHORT HBF 的带宽利用率只有 0.51，具体开销没有单独定位。
  4. 绝对吞吐系统性偏低，为论文的 0.37–0.80×（上一轮 0.26–0.72×），差距来自 batch。23 个论文 SLO 受限点的 TPOT 比为 0.50–0.98，全部低于论文，batch 比为 0.25–0.77。其中 5 点 TPOT 明显低于 SLO（49.9–77.5 ms）：继续加 batch 吞吐不再上升，或搜索停在了通过端、区间上限。7 个论文容量受限点里，native 的 6 个 HBM4 同样受容量限制，batch 比 0.77–0.94，TPOT 却是论文的 1.25–1.79×（论文 24–34 ms）；例外是 405B SHORT，DP2/TP4 使 batch 比降到 0.43，TPOT 比 0.69。Maverick SHORT HBF+ 在论文中受容量限制，在 native 中吞吐先于容量不再上升（第 3 条），batch 比 0.50。
  5. batch 偏小有多种原因，带宽用不满只是其中之一。native 选中点的带宽利用率（每 GPU 每步实际读写字节 ÷ 步时长 ÷ 标称带宽）HBM4 为 0.42–0.63，HBF 0.51–0.72，HBF+ 0.43–0.78，CONV 0.47–0.54，CONV+ 0.81–0.89，都高于上一轮。但在 23 个 SLO 受限点上，利用率与 batch 比几乎不相关（对数相关系数 0.01）：CONV+ 利用率最高，batch 比仍只有 0.46–0.67。一步的字节预算是 batch × 每请求 KV 字节 = 有效带宽 × TPOT − 权重等其它字节，按它把这 23 点分组（括号内为 batch 比）：
    • LONG 的 HBF、HBF+（4 点，0.54–0.71）：KV 占每步字节 70–86%，带宽效率的影响最直接。405B 的利用率只有 0.59–0.65；Maverick 这两点选了 DP2，每步其它字节约 205 GB，单副本权重约 100 GB。
    • CONV、CONV+（12 点，0.43–0.77）：KV 只占 23–52%，权重等固定字节把总字节差放大到 KV。405B MID CONV+ 每步总字节 181 GB，论文按单副本估算为 232 GB，少 22%，KV 字节少 50%。
    • 405B SHORT/MID 的 HBF、HBF+（4 点，0.45–0.57）：选 DP4/TP2，每步字节是单副本的 1.85–2.52 倍，KV 只占 21–39%。论文布局未公开；Fig. 4 中 405B SHORT HBF+ 从 1 到 16 GPU 每 GPU 吞吐不变，推测论文也用多副本，所以多读权重不单独算作与论文的差异。
    • Maverick MID 的 HBF、HBF+（2 点，0.25–0.33）：TPOT 只用到 50–66 ms，原因见第 3 条。
    • Maverick SHORT HBF（1 点，0.44）：利用率 0.51，选 DP2/TP1，每步字节是单副本的 1.35 倍，没有单独定位。
    论文容量受限的 HBM4 是另一种情况：除 405B SHORT 外的 5 点 batch 比 0.77–0.94，差距主要在 TPOT（第 4 条）。这 5 点 native 利用率 0.42–0.63，论文隐含利用率 0.68–0.93（（权重/8 + 论文 batch × 每请求 KV 字节）÷ 论文 TPOT ÷ 标称带宽，按单副本估算，是下界）。两者之比 1.37–1.60，与 TPOT 比 1.25–1.79 同一量级，指向 native 按 JEDEC 支付的行切换、tRRD/tFAW、刷新；这是量级对照，没有逐项拆分。
  6. batch 增益方向一致，幅度偏小。native 中 HBF 相对 HBM4 的 batch/GPU 增益为 0.98–3.91×，HBF+ 为 1.08–4.30×；论文图读数为 1.31–4.51× 和 1.67–5.31×。两边都是 LONG 增益最大；HBF+ 高于 HBF 都是 5/6 个负载，唯一例外都是 Maverick SHORT。405B SHORT HBF 为 0.98×，是唯一没有增益的点（这里 HBM4 的最大 batch 是 TP8 B941，117.6/GPU）。论文随上下文单调增长，native 有两处不单调：405B MID HBF+（1.48，低于 SHORT 的 1.59）和 Maverick MID HBF（1.38，低于 SHORT 的 1.56），这两点都停在通过端，比值被低估。native 值是下界：取全部实测点中 TPOT 上界 ≤ 100 ms 的最大 batch，含最大 batch 搜索的接受点，仍受预测区间和搜索步长限制。
  7. 墙钟不影响这份对照；有 4 个 case 的选中点受 forecast 区间限制。最终审计：可能改变结果的墙钟受限布局 0 个，因墙钟被拒的点 0 个，最长单点 13892 s，上限 21600 s。区间限制与墙钟无关：选中结果标为“区间上限”的是 405B CONV MID、405B HBF SHORT、Maverick CONV SHORT、Maverick HBF+ MID。另有被拒点的估计吞吐高于选中值的 4 个 case，高 4–7%（405B CONV MID 174 vs 165、405B HBF+ MID 1070 vs 1020、Maverick CONV SHORT 1942 vs 1812、Maverick HBF+ SHORT 7244 vs 6958）；只有区间乐观端更高的 3 个 case 为 405B CONV+ MID、405B HBF SHORT、Maverick HBF SHORT。把这些值全部代入，60 对排序的结果不变。

口径与差异来源

对齐的构造

  • 同一模型（Llama 3.1 405B、Llama 4 Maverick，BF16）与 Table I 五种硬件参数。
  • 同一负载均值 ⟨1,660, 373⟩、⟨5.9K, 499⟩、⟨103.5K, 1.1K⟩，Decode 节点 PD 分离，连续批处理补位。
  • 在容量、SRAM 与 TPOT ≤ 100 ms 约束下，搜索 DP/TP/PP/EP 布局与 batch，取每 GPU 吞吐最大者。

论文为达到峰值所做的简化（native 不采用）

  • 硬件按标称峰值、效率 1；存储为恒定带宽。native 用 JEDEC HBM 时序（行冲突、tRRD/tFAW、刷新）和 NAND 页读/平面并行。
  • 理想 Prefill 节点、批处理零停顿。native 的 PD 导入要付出 KV 写入时间与导入池等待。
  • SRAM 只放中间激活。native 的 HBF+/CONV+ 还把 KV 尾块暂存在 SRAM，放不下的写 NAND。

native 已知建模缺口

  • HBM 地址映射为线性混合基交织，没有厂商的 XOR 哈希；NAND 无 FTL/GC，尾页写入按地址固定落到 plane，控制器不做均衡，也没有编程挂起。
  • HBM 的 FR-FCFS 只在同一批请求内重排。
  • GPU 计时为 roofline（峰值 × 效率 + L1/L2 复用），没有 SM/warp 周期模型。

读数精度

  • 论文 HBM4 绝对值为图上取整标注；其它 Fig. 4 值由 PDF 矢量坐标读出，约 ±0.01；Fig. 3 batch 比约 ±0.02。
  • native 全部 30 个 case 完成，所有选中布局均为 PP1。KV 为多 rank 物理分页（256 token 一块）。没有结果受墙钟限制；搜索结论为“区间上限”的点是下界，上限来自 forecast 区间过宽。
