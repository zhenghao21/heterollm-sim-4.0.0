# Decode 仿真速度优化结果

更新：2026-10-16 22:57（北京时间）。

**本轮优化已结束，十倍目标未达到。** 按用户要求，额外三种方法均已尝试；它们没有稳定的完整 Decode 收益，试验代码已全部撤销，保留此前经过等价检查的最佳实现。用户已要求提交推送后恢复正式扫描，实时状态见 [扫描报告](../b200_hbm_hbf_0_5b_7b_20261016/report.md)。

## 最终同长度对照

Qwen2.5-0.5B、单 B200、BF16 权重/KV、单请求；输入 65,536 token，输出 17 token。完整执行 16 个 Decode 步骤，性能统计取分析器尚未启用的前 8 步。基线为提交 `1645b4f`。

下表为本机运行仿真器的真实耗时，不是模型预测的 TPOT。

| 部署 | 原版秒/Decode 步 | 最终版秒/Decode 步 | 加速 | 最终结果 |
| --- | ---: | ---: | ---: | --- |
| HBM | 6.6584 | 1.0410 | 6.40× | [完整结果](final_64k_HBM.json) |
| HBF | 3.5805 | 0.6357 | 5.63× | [完整结果](final_64k_HBF.json) |

两组最终完整结果的所有非运行耗时字段，以及全部 48 个 cohort 的仿真完成时刻，均与对应基线完全一致。包括 TTFT、TPOT、请求指标、资源占用、存储流量和部署结果；比较未使用数值容差。

最终两组顺序执行，Decode 计时窗口没有分析器、并行扫描或其他性能测试。结果仍受本机运行状态影响。历史基线的两个进程曾同时启动，因此上述倍数用于与已保存基线比较，不能当作严格隔离的硬件性能结论。

这些是仿真器性能对照，不是正式 1K/5K/10K 输出扫描结果，也不能代表 1.5B～7B 或 256K/512K 输入具有相同加速。

## 最后三种方法

以下均用完整统计执行，不减少 Token、物理访问或统计字段。整步选择对照使用 32 token 输入、9 token 输出，并按原版/候选/候选/原版交错运行，每轮统计 8 个 Decode 步骤。

| 方法 | 相对此前版本的整步加速 | 结论 |
| --- | ---: | --- |
| HOST 访问与链路批处理 | 1.0049× | 小于运行波动，撤销；[记录](method1_host_summary.json) |
| HBM 时钟函数内联 | 0.9996× | 局部核心有提升，完整 Decode 无收益，撤销；[记录](method2_inline.json) |
| HBM 资源日历编译检查 | 0.9968× | 局部检查更快，完整 Decode 无收益，撤销；[记录](method3_calendar_summary.json) |

三个候选的全部结果字段及 cohort 完成时刻均通过精确对照。没有把局部微基准收益当作完整仿真收益，不再追加优化方案。

## 最终保留的累计改动

- HBM 数值核心的精确重复周期处理、按通道执行，以及控制器状态的选择性装入和发布。
- HBF/NAND 页批处理、HOST 暂存状态复用及事务撤销；空闲 HOST 页队列发生修改时才保存撤销副本。
- 复用静态任务片段，每步重建动态 KV、地址与分配代次。
- 合并资源统计的重复汇总，使用四个同源码 Cython 辅助模块减少对象转换。
- 为地址分配维护有序索引，减少重复排序与扫描；只读任务省去无用的读写冲突索引。
- 修复重复浮点加法跨指数边界时的舍入问题，保持与逐次加法一致。

没有采用抽样、外推或减少统计字段的执行模式。未证明收益的资源账单重构、整模块 HBF 编译和本轮三项候选均未保留。

## 检查与运行状态

相关回归累计覆盖 897 个不同用例。首轮 868 项中 865 项通过；3 项暴露已有 GDDR 预设缺少必填控制字段。补齐 GDDR 与本机 DDR5 预设中原有默认值后，失败文件及三代 GDDR/本机 DDR5 拓扑的 38 项复测全部通过，严格参数校验保留。

覆盖内容包括逐事务结果、控制器完整状态、浮点边界、资源别名、字典顺序、嵌套回滚、动态 KV 绑定、调度、完整统计及公开接口。四个扩展已按最终源码重建；最终 64K 两组完整等价对照通过。

优化结束时正式扫描为暂停、0/72。用户随后要求提交推送当前最佳版本并恢复扫描；后续进度由 [正式扫描报告](../b200_hbm_hbf_0_5b_7b_20261016/report.md) 持续更新，本报告保留优化测量结果。
