## 已确认的主要瓶颈

每个 cohort 先在独立环境执行完整命令计算以生成调度成本，之后由持久运行时正式执行。因此两次物理访问都消耗 CPU。它们的初始状态和到达时间可以不同，不能直接复用正式结果或删除其中一次。

70B 的首个 prefill 图有 2,596 个任务、2,254 条物理访问，共 142,866,707,334 字节（约 133.055 GiB，含少量主机 DDR）。这些访问组合全部不同，最大的单请求为 2,101,346,304 字节。监控已观察到数值执行占主要耗时；端点预览很少，再加端点预览缓存对本批收益有限。

`round1` 四点首个独立成本计算均已完成，各耗时约 27.3–28.3 分钟，并进入正式执行。因此此前长时间没有完整结果不代表卡死。这只是本机该轮部分阶段的耗时，不能当作完整仿真时间或最终版本加速比。

当前监控的 `isolated_cohort` 与 `other_or_live` 分开统计。底层调用累计字节包含独立成本计算和正式执行，不能当作最终模型正式访存量；后者应以完成结果中的 `core_execution_audit` 为准。运行期间的 MB/s 是仿真器处理速度，也不是被模拟硬件的带宽。
