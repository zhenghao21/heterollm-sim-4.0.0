原 DLL 指令证据已明确：正常量化路径为 `RCP(amax) -> RN_FTZ(*127) -> RN_FTZ(*x) -> round-half-away`，scale 路径为再次 `RCP(inverse)`。0x0540 与 0x07d0 是这两处倒数；0x0170 的倒数属于索引计算，不能混入量化数值解释。

舍入链也与 source 的 roundf 语义一致。HFMA2 常量形成 0x3f000000，即 float 0.5；LOP3 的 b8 真值表实现 `(half & ~sign_mask) | (product & sign_mask)`，形成带 product 符号的半单位。FADD.FTZ.RZ 加半单位后向零舍入，再 F2I.TRUNC.NTZ 截断。在有限、正常、量化范围内，这等价于最近整数、平局远离零；向零的加法避免把恰好低于整数边界的和再舍入到整数。目标 63.499996... 因而变为 63，而 63.5 变为 64。

数值误差推导必须带前提。NVIDIA CUDA 12.8.1 PTX 文档为 `rcp.approx.f32` 指定最大一 ULP 误差；本 DLL 的可执行 fatbin 没有 PTX，SASS 的 MUFU.RCP 助记符本身不足以把这个精确数值契约绑定到该二进制。以下为**条件性正常数值域证明和诊断**，不能据此给生产转换 gate 发放通过。原始文档地址、响应哈希和核对记录在 `primary_documentation_evidence.json`。

令 `u = 2^-24`，即 binary32 最近舍入的相对误差界。若倒数误差按正确舍入值的一 ULP 衡量，设 h=RN(1/A)，则 `|h-1/A| <= u/A`，且 `ULP(h) <= 2u*|h|`。由三角不等式，一个同时覆盖“相对精确值的一 ULP”和“相对 RN 值的一 ULP”解释的保守相对界为：

```text
rho  = 3u + 2u^2 = 1.7881394143159923e-7
alpha = (1+rho)(1+u) - 1 = 2.384185968651313e-7
  |inverse/(127/A) - 1| <= alpha

tau = (1+rho)(1+u)^2 - 1 = 2.980232558513777e-7
  |product - 127*x/A| <= |127*x/A| * tau <= 127*tau
  127*tau = 3.784895349312497e-5

(1-rho)/(1+alpha) <= scale/(A/127) <= (1+rho)/(1-alpha)
0.9999995827675612 <= scale/(A/127) <= 1.0000004172326378
```

上述推导要求输入为有限 binary32，非零输入为正常数，A>0，所需倒数、乘法和非零 product 均处于有限正常范围；0 输入可单独精确处理。本离线工具还要求用于界计算的精确倒数处于其正常数参考域，否则明确返回不支持。FTZ 的次正规数、A=0、上溢/下溢、NaN/Inf 不在该证明内，不能把它描述为覆盖所有浮点输入的转换验证。

量化是整数阈值运算，不能把小的相对倒数误差当成小的码误差。只有精确 product 到最近半整数阈值的距离大于上述绝对误差界时，才能唯一决定 q。阈值附近必须保留允许码集合。x=A/2 这一普通输入构造使精确 product 恒为 63.5；同一误差契约允许阈值两侧的 product，从而允许 q=63 或 q=64。这个反例不依赖行号、随机种子或矩阵形状，足以否定“只由 CPU 正确舍入 source 算式就能得到跨设备位精确近似倒数结果”的主张。

`normal_domain_envelope_audit.py` 使用精确有理数计算这些边界、精确 binary32 最近舍入和候选枚举。对于每个 32 元素块，它要求**同一个候选 inverse**同时解释全部 32 个码，并且实际 scale 也满足第二个倒数的候选范围，而不是分别替每个码选择最有利结果。

冻结输入中的 2,048 个块全部处于本诊断支持域；全部有联合候选路径，65,536 个码和 2,048 个 scale 均没有超出条件范围。共有 4 个输入位置允许多个码。目标块的 q63 和实际 scale 同时符合 inverse=254.68394470214844 的候选路径；这是由假设和输出约束得到的候选，**不是捕获到的设备寄存器值**。

观察到的 scale 与原 CPU source 参考之间的位步差分布为 `-3:19, -2:184, -1:281, 0:1223, +1:204, +2:130, +3:7`。因此，统一下调一 ULP、只改第11行第33码、或把 CPU reciprocal 换成某一固定方向都没有全输入依据。
