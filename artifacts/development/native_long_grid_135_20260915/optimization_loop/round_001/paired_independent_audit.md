- 混合模型从逐请求decode批次变成mixed加多请求decode；非混合模型与单并发控制锚点指标不变。所有候选请求原生P和O−1解码逻辑token计数完整守恒。
- 27B GPU P128/C4：O128→O256候选TTFT保持797.804ms不变；基线9117.318→17885.009ms。改变来自首token完成事件与批次构成，不是起点移位。
- CPU 27B P128/O32/C4：TPOT转向更接近原生，但请求中位E2E变差；批次整体span反而下降。必须分别保留这两个聚合口径。
- GPU P1536/O32/C4：候选span接近原生，但TTFT仍高。仿真前四次prompt chunk按request 0/1/2/3轮转，四个engine起点挤在0–253ms；原生三次重复起点按序约0/1446/3730/6166ms。首token定义相同，候选选择/分配prompt工作的顺序与原生不同。
- 原生server iterate按slot向量顺序执行，pending prompt在剩余batch预算中连续填充；仿真默认least_recently_served轮转。下一轮应审计这一调度语义，不应因span误差较低就挪动engine起点。
- batch_schedule.start_ns有排队/预约含义，部分请求早于engine begin。此字段与首个实际engine processing事件不等价。
- 已验stage ID不重复、host prefix至多一个、所有候选token守恒；operator_invocation_groups与深层任务明细被截断，无法据此保证所有同步/物理拆分成本无遗漏或重复。
