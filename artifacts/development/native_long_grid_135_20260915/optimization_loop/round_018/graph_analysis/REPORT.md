表中主机数据来自各direct进程的QPC，设备数据来自独立profile的Nsight时钟。二者不得相减成“launch缺失常数”，也不能把同步wall与所包含的GPU时长相加。18对中10对direct波动超门限、11对profile/direct差异超门限，失败重叠，全部保留。

当前探针每图后进行tensor_get、全量CPU数值验证和记录写入。它们在计时边界外，仍会改变下一次调用前的间隔、缓存和驱动状态；大buffer的验证间隔明显不同，因此不能仅凭低GPU工作占比推断缺失一个通用固定开销。

下一条可证伪假设是调用间检查改变driver批处理与提交/同步节奏。后续必须新建协议，将预先规定的计时块和数值审计块分离，并保留启动身份、每块首末数值、缓冲状态与观察扰动。该假设尚未验证，当前数据不生成任何系数。

此处是单后端合成SCALE图，不证明LLM图构造、混合卸载或多请求调度等价。每阶段原始QPC与完整Nsight事件留在collection，analysis.json保留逐调用并集、交集、分区和调用前间隔。
