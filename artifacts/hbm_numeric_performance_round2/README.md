# 第二轮 HBM 数值核心优化调查

**accepted = none。** 本轮没有采用新的运行时优化。`src/heterollm_sim/_hbm_numeric.py` 已恢复到本轮开始的版本，保留上一轮已验证的行命中计算复用和请求常量外提。本轮候选均未保留在产品运行路径中。

本轮发现每次 ACT 后扫描通道全部 bank 的活动期限有优化空间，但正确性边界修复后的真实请求性能没有稳定改善，因此撤回。新增维护与恢复状态回归测试、可重复运行的诊断脚本改进予以保留。

## 测量方式

- 配置：`hbm3e_timing_reference`，512 GiB，读写预算各 1600 GB/s，接口 6553.6 GB/s，时钟 0.625 ns，all-bank refresh。
- 真实工作点：448 MiB（469,762,048 B），到达时刻 1,000,000,000 ns；这是运行中的 70B 实验常见权重请求大小。
- 冷态从空状态开始；续接先执行同样大小的请求，再测相邻地址的下一次请求。
- 短请求：65,536 次 32 B 请求，在同一 bank 的两行之间切换，混合读写。入口修复版的短请求到达时刻是 0 ns，最终合并版是 1,000,000,000 ns；不能把这两次的绝对耗时当作同工作点直接比较。
- 先预热编译，数组复制不计入数值执行计时。每轮交换基线与候选的执行顺序，表中是各组耗时中位数。速度比为基线 / 候选，大于 1 才是加速。
- 测量时其他 70B 进程仍在运行；因此同时记录进程 CPU 时间。最终合并版的 CPU 速度比也小于 1（冷态 0.966、续接 0.956），与实际耗时结论一致。

128 MiB、到达时刻 0 ns 的早期试验曾显示正收益，但不能据此声称在实际大模型工作点中更快。数值核心的源码布局会影响编译器生成的代码；减少 Python 源码中的操作数并不必然减少最终执行时间。本轮不保留这些不稳定的候选。

## 正确性边界

独立审查发现：打包器允许恢复状态中存在已打开的行，但缺少其控制器地址映射。旧实现只会在地址补齐后的下一次 ACT 全扫描时纳入该 bank 的期限。直接维护增量最小值会漏掉该期限；补映射时提前加入期限也会改变原行为。

本轮先后验证懒标记和请求入口检测修复，均保持原来的发现时点。最终合并扫描候选通过独立 288 对连续、恢复及异常请求检查：返回结果、异常类型与消息、14 个状态数组逐字节一致。不过性能未满足采用条件，因此整项撤回。

已恢复的正式代码通过 89 项回归，覆盖编译控制器、FAW、上一轮行命中复用、期限最小值替换、期限相等、刷新交叉、负零到达时刻、溢出拒绝以及缺失映射恢复状态。恢复态测试包含旧实现的明确完成时间 10,605 ns、9,925 ns 和 5,557 ns。

诊断脚本 `scripts/benchmark_hbm_numeric.py` 现在逐项比较返回标量、计数和状态数组的 dtype、shape 与字节内容，可以区分正零和负零。该严格检查用于 `benchmark_merged_fixed_final.json`。更早的基准使用数值相等检查，不能单凭其 `exact_request_results_and_all_arrays` 字段声称浮点逐位一致；另行执行的边界矩阵使用了字节比较。

## 文件含义

- `benchmark_merged_fixed_final.json`：最后一次合并入口扫描候选的完整三组基准，候选被拒绝。
- `benchmark_final_448mib.json`：较早的通道懒标记修复试验，候选被拒绝。文件名中的 `final` 不代表采用。
- `benchmark_final_short_requests.json`：独立入口扫描修复的短请求试验，候选被拒绝。
- `benchmark_entry_fixed_448mib.json`、`benchmark_entry_fixed_continued_448mib.json`：独立入口扫描修复的大请求试验。
- 其余 JSON：各早期候选诊断数据，不代表正式代码的加速结论。

JSON 中的临时源码路径记录测量时加载的位置；同一临时候选文件在调查期间经过修改。对应版本以本说明中的方案及文件归属为准，不能把历史 JSON 都解释为当前路径文件的结果。旧实现和候选仅用于此次对照，不作为产品回退分支。

后续可用同一个诊断脚本对实际准备采用的版本重复测量，例如：

```powershell
.venv/Scripts/python.exe scripts/benchmark_hbm_numeric.py --mib 448 --arrival-ns 1000000000 --repetitions 3 --case cold_read --case continued_read --case alternating_row_conflicts --baseline-source <待对照源码路径> --output <结果路径>
```
