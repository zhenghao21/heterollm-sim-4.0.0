### 本轮确认的问题

| 编号 | 原有错误及复现条件 | 修复及实际影响 |
|---|---|---|
| 1 | 多个物理 owner 共用资源时，报表在每个 owner 行重复加入整个任务 demand，放大流量和忙时 | 按 owner 的 `resource_bytes`、`resource_busy_ns` 汇总；同介质和混合 DRAM/NAND 共用链路都保持总账一致。旧格式若缺少共享资源的 owner 字节分项，明确拒绝无法归属的账单；单 owner 旧格式仍可使用 |
| 3 | 用 `(resource, start, end)` 集合去重，把多槽资源上的真实并行操作合并；两条重叠 CAS 共忙 5 ns，图中只剩 2.5 ns | 仅按次数消除 payload 与 stage 的同一操作副本，保留真实操作的重数。完整和受限 payload 记录都验证忙时和字节守恒 |
| 4 | 一个任务多次访问 NAND 时，全局观测可能只保留最后一次；前次记录被截断、后次完整时，全局标志错误，或后次有效阶段也被丢弃 | 合并所有访问的 NAND 观测与截断标志；已保留的完整阶段继续有效，不把部分记录包装成完整记录 |
| 5 | Core 数据资源通过别名映射到预估资源，预估 demand 可能未被识别为已替换项，造成重复计费 | 按最终实际资源名识别并替换预估项；保留普通计算需求 |
| 6 | 开启详细记录后，阶段结束时间覆盖多槽资源的最早空闲时间；两个槽中仍有空闲槽，后续普通任务却被迫等待 | Core 日历中的最早空闲槽始终是可用时间依据；按实际推进的槽更新前驱信息，无法确认时不虚构阻塞者。详细和简化记录模式执行时间一致 |
| 7 | DRAM 从多槽缩为单槽、加速执行，再扩为多槽后，残留旧方向历史；原应等待 50 ns 写转读，却按旧读方向直接开始 | 编译单条、编译批量和 Python 折叠的单槽提交清除过期多槽历史。最小例子由 101 ns 修正为 151 ns，与逐 burst 一致 |
| 9 | NAND 暂存读取尚在 host 接口传输，program 已完成，源缓冲就被释放并复用；复现中读到 1034.24 ns 才结束，后续写却在 50.72 ns 已确认 | 源缓冲保留至 program 和暂存读取都完成。单独报告介质排空完成与缓冲释放时间，不把读取保留时间收费为 program 时间 |
| 10 | 取消迁移、释放 KV 页或结束 relay 后，NAND 的脏暂存页仍存在，之后可能向已释放地址执行无用 program | 释放独占、完整页范围内尚未排定 program 的脏暂存数据，保留已发生的 host 流量与尚未结束的源读取保留时间。邻接分配和同 owner 目标页不受影响 |
| 11 | 迁移回调生命周期未完整纳入状态恢复：异步旧回调可重复执行或把实际 1,075,033.57 ns 错记为旧的 76,503.93 ns；同步计划在恢复后重新提交却静默跳过，绑定仍在源端、账单为零；完成计划还持续留在活动表中 | 同步和异步计划统一使用可恢复活动状态及不回拨的阶段标识；过期回调不得推进、取消或提交，快照内有效计划可继续执行。终结计划立即从活动表移除，避免长期迁移累积状态及复制开销；当前运行分支重复提交仍不会重复计费 |

## 发现与修复

| 编号 | 条件和原有错误 | 修复与影响 |
|---|---|---|
| 1 | 调度器声明 Core 数据资源与普通任务共用 `wire`，普通任务已占用 0–1000 ns，HBM 数据仍可能在 28 ns 开始，绕过争用 | Core、普通任务和 KV 链路统一解析实际资源名，共用执行日历及字节账户。DRAM 相关别名安全回退到逐 burst；无关别名不关闭加速。物理 bank 身份保持独立。低层别名链解析幂等，循环显式拒绝 |
| 2 | 一个资源的两个执行槽分别刚读、刚写，却只保存全资源的最后方向；既可能漏收，也可能多收方向切换时间 | 每个槽维护方向，按加上切换时间后的可用时间选择槽。DRAM 总是传入目标方向对应的切换约束。最小 DRAM 例子从错误的 101 ns 改为 151 ns；切换等待仍不计成数据忙时 |
| 3 | 多槽 NAND 阵列擦除在 2000 ns 才结束，后续全页写却能在 281.92 ns 完成，还会倒退阵列时钟 | program 显式等待该物理阵列已排定操作完成；逐页和加速路径都使用同一依赖 |
| 4 | 非执行 array 的虚拟就绪名称恰好与尚未初始化的真实 channel/host 同名，逐页路径与加速路径初始化日历的时机不同 | 对这种初始状态回退逐页，资源建立后仍可加速。复现中原结果分别为 102157.406 ns、101866.641 ns，原加速少算约 291 ns |
| 5 | 空 `flush` 在已经观察 1000 ns 后传入 1 ns，仍可能返回 1 ns | 排空报告使用不早于已观察时间的时刻，同时保留尚未完成的排空依赖 |
| 6 | 明确允许 `block_erase_ns=0`，但上层因没有正忙时而拒绝合法擦除 | 保留擦除次数和真实完成条件，允许零成本擦除；不虚构传输字节 |
| 7 | `PhysicalService.price/price_batch` 在创建 runtime、执行或生成结果后失败，可能留下分配、队列、时间线，随后重试重复计费 | 显式 runtime 的公开定价入口覆盖完整事务。失败恢复调用前状态；独立预估不发布运行状态 |
| 8 | KV 整页写拆块后，前 32768 B 成功、尾部 1 B 被部分页策略拒绝，Core 已记账而 executor 仍报 0；异步后续阶段也缺少同等保护 | 整页访问及结果归并整体恢复；异步只恢复失败的当前阶段，保留源读取和其他已交错执行的任务。已受外层保护的块不重复创建事务 |
| 9 | NAND 批次前一请求有效、后一请求越界/部分页拒绝/超过写缓冲，验证后一条之前已经执行前一条 | 批次先验证全部请求的已知合法性，再执行。运行中的非输入异常仍由拥有该调用的上层事务处理 |
| 10 | runtime 保存点保留当前 interval 容器引用；保存后直接执行 link transfer，没有经过 Core 重置记录器，会把保存点也改掉 | 复制当前请求的区间、载荷和 touched 集合；恢复时也独立复制，多次恢复不污染保存点；同时保存多槽方向 |
| 11 | 两个 owner 共用一个数据资源，只留下最后 owner 的归属；流量可能错误归属，队列等待也可能遗漏 | 按每个 owner 的实际传输字节在共享资源上求和；保留 owner 集合，每个 owner 的准入等待只计一次 |
| 12 | 16 KiB KV 页拆成四次 4 KiB RMW，计数有四读四写，但观测记录只剩最后两个事件，配置 plane 数从 8 加成 32 | 观测记录使用专用合并规则，保留全部八个事件和八个 plane，重新计算队列、负载和磨损统计 |
| 13 | 有限参数相加仍可能产生无穷时间；DRAM recovery 可把 bank 时钟污染为 `inf`，事件层验证又在 Core/L2 提交之后，失败任务会丢出就绪队列 | 日历在提交前拒绝不可表示时间；DRAM 仅对极值请求私下预执行检查，普通请求不复制状态；事件有限性验证纳入 Core/L2 事务并保留待执行任务 |
| 15 | 巨大整数 P/E 计数在零增长时也可能浮点转换溢出；中间乘积溢出还可能错误直接饱和 | 零增长不做无意义乘法，溢出边界用精确比例后应用有限上限；无法用 float 表示的寿命比例明确标记缺值，保留原始整数，不伪造有限结果 |
| 16 | DRAM Python 加速回退为每个 inner burst 重复建立相同映射；4 MiB interleave 小请求先生成 65536 个相同条目，约 524 KiB，特殊几何可更大 | 每个 bank/lane 只存一条映射，按 inner 索引；超大 bank×lane 几何按实际请求 burst 回退，避免建立无关全表 |

## 执行语义与成本边界

HBM 请求仍由 DramCore 执行，HBF/SSD 请求仍由 NandCore 执行。GPU 算子计算时间继续使用现有简化模型。本轮没有增加 HBM 聚合带宽替代分支，也没有把 Core 微基准等同于完整 LLM serving 实验。

DRAM 的成本来自真实拆分后的完整 burst、bank 行状态、列命令、数据资源、方向切换及恢复依赖。NAND 区分页阵列操作、内部 channel、host 接口，以及写确认和介质排空。逻辑字节、介质字节和链路字节不能互换。等待影响完成时间，但不自动算成额外传输或忙时。

## 尚未建模的内容与结果使用限制

- DRAM 仍不是完整 JEDEC 模拟器：没有完整刷新、tFAW/tRRD/tRAS、bank-group 特定约束或 FR-FCFS。PRE/ACT 占 bank，但没有另占命令总线。这些会影响硬件预测精度，不等于已模拟且成本为零。
- NAND 没有真实内容位、FTL、真实 GC、隐式擦除、掉电持久性。重复暂存写按累计 host 载荷占缓冲；页级暂存和 RMW 也有保守依赖。host 粒度不整除页大小时，按各页片段独立对齐收费，这是当前合同。
- Core 不自动推断跨任务的数据依赖；上层必须提供操作因果关系。物理时序正确不代表可以任意并发访问同一逻辑 KV 数据。
- 浮点加速允许正常容差内的舍入差别，未证明所有可能参数逐位相同。公开运行事务能处理失败恢复，但直接低层 Core 的任意自定义回调异常不承诺完整事务原子性。
- 异步取消保留已经发生的物理流量；不能为取消一个迁移而撤销其他已交错任务。本轮只把失败阶段恢复到开始该阶段时的状态。
- 本轮没有重跑此前的 19 组大规模实验，因此 `results.json`、已有 TPS 图与 HTML 报告仍是历史仿真结果。对触发这些缺陷的场景，不能宣称原数字仍然有效；对未触发场景，也没有用本轮小回归代替完整重跑。

本轮已确认的可复现缺陷均已修复。上述模型边界保留并明确披露；有限审计不能证明不存在其他问题。
